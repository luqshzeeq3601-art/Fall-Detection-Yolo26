## 1. State diagram (text)

```text
                    frame                      silence > degraded_after
           ┌─────────────────────┐            ┌──────────────────────┐
           │                     v            │                      v
         ┌──────────┐  frame   ┌────────┐  silence   ┌──────────┐  silence  ┌─────────┐
         │ UNKNOWN  ├─────────►│ ONLINE ├───────────►│ DEGRADED ├──────────►│ OFFLINE │
         └──────────┘          └────────┘            └──────────┘           └─────────┘
              │                  │  ▲                  │  ▲                   │  │
              │ silence          │  │ frame             │  │ frame              │  │ frame
              │ > degraded       │  │                   │  │                   │  │
              v                  │  │                   │  │                   │  │
         ┌──────────┐  silence   │  └───────────────────┘  └───────────────────┘  │
         │ DEGRADED │◄──────────┘  (frames recover to ONLINE from ANY state)      │
         └──────────┘                                                            │
              │ silence > offline_after                                           │
              v                                                                   │
         ┌─────────┐  frame                                                       │
         │ OFFLINE ├──────────────────────────────────────────────────────────────┘
         └─────────┘
```

Notes:

- Deep silence jumps directly (`ONLINE → OFFLINE`, `UNKNOWN → OFFLINE`)
  because the rule is evaluated as `> offline_after` first, then
  `> degraded_after` — no forced stepping through `DEGRADED`.
- `poll()` never recovers towards `ONLINE` (a shrinking silence under clock
  skew just yields no transition); only `notify_frame` recovers.
- Pre-first-frame silence is measured since construction (`created_at`), so
  `UNKNOWN → DEGRADED → OFFLINE` progresses with no frames ever.

## 2. Boundary table (strict-greater contract)

Defaults: `degraded_after=2.0`, `offline_after=10.0`. Silence `s` measured
from the last accepted frame (or construction when none).

| `s` vs threshold | From `ONLINE` | From `DEGRADED` |
|---|---|---|
| `s == degraded_after` | stays (`None`) | stays (`None`) |
| `s == degraded_after + ε` | → `DEGRADED` (`silence-degraded`) | stays `DEGRADED` (`None`) |
| `s == offline_after` | stays if still `ONLINE` (`None`); stays `DEGRADED` (`None`) | stays (`None`) |
| `s == offline_after + ε` | → `OFFLINE` (`silence-offline`) | → `OFFLINE` (`silence-offline`) |

All four boundary rows are pinned by tests (`test_4a`, `test_4b`,
`test_9c`); the `UNKNOWN` pre-frame pair by `test_5`.

## 4. Design decisions

- **Reason strings**: `frame-received` / `silence-degraded` /
  `silence-offline` (module constants `REASON_*`; lowercase hyphenated, no
  dots so they cannot be mistaken for emitted event codes — this module
  emits no camera events; the only log event is `stream.health.transition`).
  `REASON_INITIALIZED` deliberately NOT defined (no init transition).
- **`created_at = clock()` once at construction** anchors since-creation
  silence; one clock read per `poll()`/`silence()` call, always outside the
  lock. `clock()` output is validated like any other timestamp.
- **`silence()` returns since-creation when no frame yet** (never `None` in
  practice; the `float | None` annotation retains brief signature
  compatibility).
- **Equal timestamps accepted** (only strictly-older frames ignored);
  `bool` rejected as timestamp (exact-type guard, not just `isinstance`).
- **Threshold check is one relation** (`0 < degraded_after < offline_after`,
  `ValueError` naming both names and both values); NaN fails the relation
  automatically. `+inf` `offline_after` passes the relation and is accepted
  (never-offlines) — documented, not tested, out of brief scope.
- **`camera_id` requires plain non-empty `str`** (shape allowlist stays in
  `CameraConfig` P1-001 upstream; documented layering).
- **Logging**: bound `service="vision"`, `component="stream.health"`,
  `camera_id`; transition materialised under the lock, `logger.info`
  emitted after release (no I/O under lock). `from_state`/`to_state`/`reason`
  travel as record `extra` (land in JSON `extra`, not top-level — matches
  `JsonFormatter` stable-key rules); `camera_id` is top-level by formatter
  design.
- **`__repr__`**: `StreamHealthMonitor(camera_id=…, state=…, silence=…s)` —
  scalar only, URL-free by construction (test-scanned).

## 7. Assumptions

- `time.monotonic` seconds share a domain with caller-supplied frame
  timestamps (same assumption as the queue/capture handoff; callers must
  use one clock domain).
- `threading.Lock` (non-reentrant) released correctly on any unwind via
  context manager; interpreter-teardown races out of scope.
- Log-record `extra` keys (`from_state`/`to_state`/`reason`) asserted via
  direct attribute access in tests (runtime attributes set by stdlib
  logging from `extra`); repo gates run ruff + pytest only (no mypy).

## 8. Limitations

- Single-process `threading` design; no cross-process/async support.
- `state`/`last_frame_at`/`silence()` each take the lock separately — no
  atomic multi-field snapshot (same caveat as P1-003 counters).
- No eviction/history of transitions, no event emission, no reconnect —
  explicitly later tasks (P1-005+).
- Infinite `offline_after` is accepted (relation holds); NaN thresholds
  rejected via the same relation check.
