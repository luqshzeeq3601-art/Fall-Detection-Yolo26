# P1-001 Implementer Report — Camera config model

## Contract table

| Field | Type / default | Constraints | Notes |
|---|---|---|---|
| `camera_id` | `str` (required) | `min_length=1, max_length=64`, pattern `^[A-Za-z0-9_-]+$` | Stable identity; is the `camera_id` key of the frame observation (`ARCHITECTURE.md` §5). Maps to `id` in `API_SPEC.md` §3 (`id` ↔ `camera_id`). |
| `name` | `str` (required) | `min_length=1, max_length=128`; surrounding whitespace stripped, whitespace-only rejected | Human-readable; aligns with API §3 `name`. |
| `enabled` | `StrictBool = True` | Strict bool — `"true"`/`1`/`0`/`None`/`1.0` all rejected | No truthy-string coercion. |
| `rtsp_url` | `str` (required) | Scheme MUST be `rtsp`/`rtsps` (case-insensitive), hostname required, port numeric when present; empty REJECTED; credentialed URLs ACCEPTED | Raw value never surfaces (`__repr__`/`__str__`/`model_dump_safe()` render via `redact_rtsp_url`). |
| `location` | `str \| None = None` | `max_length=128` | Inert metadata; no runtime reads it. |
| `description` | `str \| None = None` | `max_length=512` | Inert metadata; no runtime reads it. |

Model: `CameraConfig(BaseModel)`, frozen (`ConfigDict(frozen=True,
hide_input_in_errors=True)`). Pure function
`ensure_unique_camera_ids(configs) -> None` raises `ValueError` naming the
duplicated `camera_id`; no logging inside, no registry, no connection logic.
Validation lives only in the model (boundary); nothing scattered elsewhere.

### Deliberate differences from P0-005 `Settings`

- Scheme narrowing: `Settings.RTSP_URL` accepts any `scheme://host` URL;
  `CameraConfig.rtsp_url` accepts only `rtsp`/`rtsps` (this is the RTSP
  stream manager).
- Empty handling: `Settings.RTSP_URL == ""` means "disabled" (global
  default); `CameraConfig.rtsp_url == ""` is a configuration error and is
  rejected (a camera entry with no source is meaningless).
- Mutability: `Settings` is mutable; `CameraConfig` is frozen.
- Shared: both use `hide_input_in_errors=True`, and both use generic
  validator messages that never embed the input value.

`exc-leaks-user: False`, `exc-leaks-pass: False` — the option is honored

## Assumptions

- `camera_id` values are not secrets, so naming a duplicate id in the
  `ValueError` is safe; URLs are never included in that message (and the
  helper performs no logging at all).
- `model_dump()` (raw) intentionally retains the real URL for the future
  capture layer; only `model_dump_safe()` is API/log-safe (asserted both
  sides in-test).
- Port range is not range-checked beyond numeric parsing: an out-of-range
  numeric port (e.g. `99999`) raises `ValueError` inside `urlsplit().port`
  and is therefore rejected fail-closed via the generic numeric-port
  message (same safe direction, no explicit test pinned).
- Scheme comparison is case-insensitive (`parts.scheme.lower()`), so
  `RTSP://host/...` is accepted as `rtsp`.
- `strict` bool semantics come from pydantic `StrictBool`; no custom
  coercion logic.

## Limitations

- Config validation only: no stream opening, reconnect/backoff, frame
  queue, health transitions, persistence, or multi-camera runtime (per
  brief; P1-002+ scope).
- `redact_rtsp_url` rebuilds host via `hostname` (lowercases, strips IPv6
  brackets); userinfo-free URLs are otherwise byte-stable (inherited P0-005
  behavior).
- Unicode/overlong edge inputs are handled fail-closed and leak-free, but
  exotic-but-parseable URLs (e.g. the `p@ss/w?x#y z@host` shape, accepted
  with host `ss`) are validated for shape only — no semantic reachability
  check exists at this layer by design.
- No FastAPI/DB code: `model_dump_safe()` is serialization-ready per
  NFR-021 but unwired until a later phase.
