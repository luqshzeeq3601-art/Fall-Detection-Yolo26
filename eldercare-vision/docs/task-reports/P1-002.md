## 2. DI design + failure semantics

- `VideoCaptureLike` (`typing.Protocol`): `isOpened() -> bool`,
  `read() -> tuple[bool, Any]`, `release() -> None`. Fakes implement this;
  no cv2 import needed in tests.
- `RtspCapture(config, capture_factory=None)`; default factory is
  `cv2.VideoCapture`, resolved by **module-attribute lookup at each `open()`**
  so `monkeypatch.setattr(cv2, "VideoCapture", …)` intercepts it.
- `open() -> bool`: releases a prior held handle first (leak hygiene), builds
  via factory, returns backend `isOpened()`. Factory exceptions,
  `isOpened()`-raises, and `isOpened()==False` all → `False` + sanitized
  `last_error`; the failed backend handle is released before returning.
  Never raises for open-failure.
- `read() -> tuple[bool, ndarray | None]`: `(False, None)` when closed
  (handle `None`), on `(False, …)` backend flags (normalized — frame dropped),
  and on backend exceptions. Success passes the frame through untouched and
  clears `last_error`. Never raises for read-failure.
- `release() -> None`: drops the handle in all cases; safe ×N, safe when
  never opened, safe after failed open. A raising backend `release()` is
  caught → sanitized `last_error`; the seam handle is still dropped.
- `is_opened` = seam state (a handle is held), **not** a live backend poll —
  no per-call backend I/O. `last_error: str | None`, cleared on every
  successful open/read, sanitized via `sanitize_exception_message` otherwise.
- Context manager: `__enter__` opens and returns `self`, never raises for
  open-failure (check `is_opened` inside the block; reads then yield
  `(False, None)`); `__exit__` releases; body exceptions propagate.
- Logging (bound `service="vision"`, `component="stream.capture"`,
  `camera_id`; P0-006 only): `capture.opened` (INFO), `capture.open_failed`
  (WARNING), `capture.read_failed` (WARNING), `capture.released` (INFO). The
  configured URL is never passed to any log call.
- `repr`/`str` = `RtspCapture(camera_id=…, opened=…)` ONLY. Deliberate choice
  vs P1-001's redacted repr: capture state needs no locator at all, so the
  URL is **absent entirely** (not even the host) — `camera_id` suffices for
  correlation. Raw credentials are absent from `repr`/`str`/`last_error`/logs
  on every path (tested adversarially, §5 area 8).

   → `False`, user/pass/token absent from `last_error`.

5. Read `(False, None)` flag, read-raises, read-when-never-opened,
   read-after-release → all `(False, None)`, no throw.
6. Release ×3 (single backend release), release-without-open,
   release-after-failed-open (no double-release, no throw).
7. Context manager happy path (released on exit) + open-failure (enter does
   not raise; body sees closed capture; exit clean).
8. Credential safety end-to-end: credentialed config through open-failure,
   read-exception, `repr`/`str`, and captured JSON logs → user/pass/host/token
   absent everywhere; `capture.open_failed`/`capture.read_failed` present;
   happy-path `capture.opened`/`capture.released` lines credential-free.
9. Default factory cv2-backed: `monkeypatch.setattr(cv2, "VideoCapture", fake)`
   → default-constructed `RtspCapture.open()` calls it with the configured URL
   (`True` path) and returns `False` gracefully on `isOpened()=False`.
   **Justification for mocking over a nonexistent file:** deterministic and
   backend-independent — no filesystem, backend-plugin, or warning-timing
   coupling — while still proving cv2 wiring plus graceful `False`.
   Plus failure-state clearing: failed-open → success clears; failed-read →
   success clears.

## 8. Assumptions

- `is_opened` is seam state, not a live backend poll (documented in the module
  docstring); a backend dying mid-hold surfaces on the next `read()`, not via
  the property.
- `N802 noqa` on `isOpened` is required, not style drift: the name is dictated
  by the installed OpenCV API (brief-mandated protocol member).
- `read()` normalizes `(False, <anything>)` to `(False, None)`; `(True, None)`
  (degenerate backend) passes through as-is.
- Failed-`open()` releases the backend handle immediately (one backend
  `release()` per failed open); seam holds nothing afterwards.
