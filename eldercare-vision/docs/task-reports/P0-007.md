## Workflow design table

| Item | Choice | Reason |
|---|---|---|
| Triggers | `push` + `pull_request`, NO branch filter | Local default branch is `master`, not `main`; a `main:` filter would silently skip CI on the real default branch. Unfiltered triggers are master-safe. Documented in a file comment. |
| `permissions` | `contents: read` top-level | Minimal: jobs only check out code and run gates; nothing writes. |
| `concurrency` | `group: ${{ github.workflow }}-${{ github.ref }}`, `cancel-in-progress: true` | Cancel superseded PR runs; latest push per ref wins. |
| `runs-on` | `ubuntu-latest` both jobs | Standard CPU-only runner; no self-hosted/GPU labels. |
| Python version | `3.10` | Matches local 3.10.11 major; `pyproject.toml` `requires-python = ">=3.10"` and ruff `target-version = "py310"`. |
| Python cache | `setup-python` `cache: pip` | Speed up `pip install -e .` without extra config. |
| Node version | `24` | Matches local v24.14.1 major. |
| npm cache | `setup-node` `cache: npm` + `cache-dependency-path: frontend/package-lock.json` | Explicit lockfile path because the job sets `defaults.run.working-directory: frontend` while the cache input resolves relative to the workspace root. |
| Frontend working dir | `defaults.run.working-directory: frontend` | So `npm ci` / `run typecheck|lint|build` / `test` run against the frontend package without per-step `cd`. |
| Python steps | `pip install -e .` → `ruff check .` → `ruff format --check .` → `pytest -v` | Mirrors `pyproject.toml` gates (§5 inputs: Ruff + pytest). Format is check-only, never rewrites. |
| Frontend steps | `npm ci` → `npm run typecheck` → `npm run lint` → `npm test -- --run` → `npm run build` | Script names verified verbatim against `frontend/package.json` (`typecheck`, `lint`, `test`, `build` all exist; `ci`/`build` are npm builtins/wrapped scripts). Clean-install via `npm ci` (lockfile present). |
| Excluded | No services, containers, hardware labels, datasets, credentials, publish/deploy steps | Phase 0 baseline only; TEST_STRATEGY §5 GPU/video benchmarks stay local/reproducible, not per-commit CI. |
| Failure behavior | No `continue-on-error`, no `|| true` | Any gate failure fails its job and the workflow (grep proof below). |

TEST_STRATEGY §5 mapping: Ruff ✓, pytest (CPU unit/integration; GPU-required
suites excluded by repo markers, none present at HEAD) ✓, frontend
lint/typecheck/test ✓. Migration validation and secret-scan/audit are
"if configured" items — neither exists in the repo at HEAD (no Alembic, no
scan config), so no CI step was invented for them.
