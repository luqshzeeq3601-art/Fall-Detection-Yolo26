## Expiry / boundary rules (as implemented and tested)

- Activity basis: each key's LATEST accepted `TrackObservation.timestamp`
  (`buffer[-1]`; P3-003 append order is oldest → newest).
- Exact boundary: expires iff `now - last_timestamp > max_idle_seconds`
  (strict `>`; idle `==` limit survives). Tested `<`/`==`/`>` trio plus
  `max_idle_seconds=0.0` (only positive idle expires).
- `now`: caller-provided capture-clock time; no clocks/sleeps/locks/threads
  in `src`. No `time`/`threading` imports (AST-proven stdlib-only imports).
- Returns a FRESH tuple in key-insertion (dict) order, every call; no
  mutable internals exposed (mutating the returned tuple cannot affect the
  store).
- Idempotent: equal-argument repeat returns `()`; reuse-after-expiry starts
  a FRESH history (no ghosts; ages from new appends only).
- Fail-closed: `bool`/non-numeric → `TypeError`; NaN/±Inf/negative →
  `ValueError` (messages name `now`/`max_idle_seconds`); store unchanged on
  any validation failure (asserted per bad value). `max_idle_seconds` is
  keyword-only.
- Bulk-safe: keys collected into a tuple before any `del` (no
  mutate-during-iteration); 1000-stale-key reclamation tested.

## Assumptions

- `now < last_timestamp` (caller passed an older capture time) is not an
  error: idle is negative, so the key survives. The brief defines no such
  error; append-time monotonicity (P3-003) is the guard.
- `max_idle_seconds=0.0` is valid (only `-1`/negative rejected per brief);
  a key idle `> 0` expires, a key stamped exactly at `now` survives.
- Empty internal buffers cannot occur (buffers are created with their first
  append and removed whole); the `if buffer` guard conservatively retains
  any such key rather than silently dropping it.
- Ruff used was 0.16.8 (isolated `--target` install via system pip 25.3 /
  Python 3.14); venv packages untouched; no weights downloaded.
