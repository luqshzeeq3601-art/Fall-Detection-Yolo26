## 1. Implementation Summary

1. **Review Submission Endpoint (`POST /incidents/{incident_id}/reviews`):**
   - Implemented in `src/eldercare/api/routers/incidents.py`.
   - Validates incoming `IncidentReviewCreate` payload with allowed review labels (`confirmed_fall`, `non_fall`, `uncertain`), optional reviewer string (<= 128 chars), and optional notes (<= 2000 chars).
   - Returns `IncidentReviewRead` with HTTP 201 Created status and assigned unique review ID.
2. **Review Chronological Query Endpoint (`GET /incidents/{incident_id}/reviews`):**
   - Implemented in `src/eldercare/api/routers/incidents.py`.
   - Returns the complete chronological audit chain for an incident.
3. **Session Detachment & Refresh Hardening (`src/eldercare/incidents/service.py`):**
   - Added `session.refresh(...)` inside transactional blocks (`submit_review`, `attach_evidence`, `record_enrichment`) prior to closing the session context, preventing SQLAlchemy `DetachedInstanceError` when attributes are serialized by Pydantic.
4. **Strict Detector Immutability:**
   - Submitting reviews appends only to the `incident_reviews` table.
   - Core detector outputs (`fall_score`, `model_name`, `model_version`, `config_version`, `evidence_features`, `detector_state`) in `incidents` table remain 100% untouched.
