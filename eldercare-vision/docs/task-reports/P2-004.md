## Data-path table

| Stage | Type | Key fields / contract |
| --- | --- | --- |
| Capture read | `(ok, image)` tuple | `RtspCapture.read` shape; `ok` falsy or image `None` → `None`, never fabricated |
| Queue handoff | `LatestFrameQueue` payload | Opaque `np.ndarray` frame; public `get()` only; empty → `None` |
| Pipeline entry | `SourceFrame` | `camera_id` (non-empty str), `frame_id` (`>= 0`, `operator.index`, bool-rejected), `capture_timestamp` (finite, `>= 0`), `image` (3-D H×W×C `uint8`; shape/dtype checked, no pixel policy) |
| Inference | `PosePredictor.predict(image)` | Returns single duck-typed `Results` (`keypoints`/`boxes`/`orig_shape`); production: `YOLO("yolo26s-pose.pt").predict(source, device=0, imgsz=640, verbose=False)[0]`; empty list → `ValueError` |
| Adaptation | `adapt_pose_results(results)` | Normalized 17-keypoint `PoseFrame` (P2-003 contract reused as-is); `ValueError`s propagate with frame context via `raise ... from` |
| Cross-check | `orig_shape` vs image | Adapter-parsed `(h, w)` must equal `image.shape[0:2]`; mismatch → `ValueError` naming both shapes |
| Pipeline exit | `PosePipelineResult` | `camera_id` / `frame_id` / `capture_timestamp` propagated exactly + `pose: PoseFrame`; no `Results`, no image, no URL stored |
| Phase 3 handoff | track observation (future) | Consumes `pose.persons[i].keypoints` + confidences + `bbox_xyxy`; no track IDs here |

`decode_timestamp` decision (recorded): not a separate field — `capture_timestamp`
is the timestamp the pipeline acts on; pipeline-entry timing is not a stored
observation. Threading: pipeline holds no lock, spawns no threads; the single
capture-loop thread owns the call sequence, the queue remains the thread-safe
handoff. Logging: one `DEBUG` record per frame (`event=pose.frame_processed`,
`camera_id` bound, `frame_id` + `person_count` only — no URLs, no pixels).

## Assumptions

- `LatestFrameQueue` payloads are opaque `np.ndarray` frames in this
  integration (per brief); `process_queued_frame` treats the popped payload as
  the frame image and `SourceFrame` validation enforces the shape/dtype.
- `UltralyticsPosePredictor` was not exercised against real weights/CUDA here
  (forbidden in tests); its call pattern
  (`YOLO(model).predict(source, device, imgsz, verbose=False)[0]`) is taken
  from `scripts/dev/verify_pose_model.py` + the P2-002 record.
- `decode_timestamp` needs no field (see data-path table).
- `not ok` (rather than `ok is False`) treats any falsy read flag as failure;
  `RtspCapture` returns strict bools, so behavior is identical on the real path.

## Limitations

- No threaded manager loop, reconnect wiring, ByteTrack/track IDs, temporal
  logic, fall classification, thresholds, telemetry of inference, persistence,
  or benchmarks — all explicitly out of scope (P2-005+).
- `UltralyticsPosePredictor` device default `0` assumes CUDA at runtime; CPU-CI
  never imports it (lazy import; no test touches the class's `predict`).
- The two `tests/**/__init__.py` markers are a documented deviation (§8).

## §8 — Deviation from the brief (one, structural)

The brief fixes both test basenames to `test_pose_pipeline.py` (one under
`tests/unit/`, one under `tests/integration/`). With pytest's default import
mode and no package markers, duplicate basenames collide at collection
(`import file mismatch`), which breaks the brief's own `python -m pytest -q`
gate. Fix: added two EMPTY, behavior-free package markers,
`tests/unit/__init__.py` and `tests/integration/__init__.py`, so the modules
collect as `unit.test_pose_pipeline` vs `integration.test_pose_pipeline`.
No existing file was modified; no source/test semantics changed. Everything
else follows the brief exactly.
