## Findings

- **FYI — bare `user:pass` free-text pairs are out of the sanitizer contract
  (no action):** an initial probe variant used a factory message
  `backend refused {url} for dummyuser:dummy-pass-…`. The URL portion was
  redacted (`rtsp://***@…`) but the bare free-text pair survived, because
  `sanitize_exception_message` (`src/eldercare/common/redaction.py:166–179`)
  documents exactly two shapes: embedded-URL userinfo + `key=value`/`key:`
  secrets. A bare pair with no key name and no URL shape cannot be redacted
  without false positives on benign text. In-tree tests
  (`tests/unit/test_reconnect.py:282,374`) use only in-contract shapes
  (`{url}`, `token={pass}`), which the corrected probe re-verified clean.
  Real `cv2` backend errors echo URLs/codes (covered shapes). Not a defect;
  recorded so the gate is explicit that the first probe failure was a probe
  artifact, corrected and re-run green.
  Files: `src/eldercare/common/redaction.py`, `src/eldercare/vision/stream/capture.py`.
