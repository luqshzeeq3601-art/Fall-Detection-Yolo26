## 1. Design decisions

- **Payload-agnostic queue**: `LatestFrameQueue` stores opaque objects (`Generic[_T]`);
  no `Frame` contract invented (that is a later task).
- **Default `maxsize=2`** per pack `ARCHITECTURE.md` §4 (bounded queue size 1–2
  between RTSP decoder and inference worker); documented in the module docstring.
  `maxsize < 1` raises `ValueError` naming the bad value.
- **Put-return semantic (implementer's choice, contract-first)**: `put(frame) -> bool`
  returns whether a stale frame was dropped (`True` = drop occurred). Chosen because
  the drop event is the only information the caller cannot derive from counters
  alone at the call site; documented in the `put` docstring and pinned by tests.
- **Close semantics (implementer's choice)**: `close()` is idempotent, sets a closed
  flag. After close, `put` raises `RuntimeError("queue is closed")` (fail-fast, so a
  dead producer is loud) while `get` keeps draining retained frames and returns
  `None` once empty (so a consumer can finish gracefully). Documented + tested.
- **Thread-safety**: single `threading.Lock` guards all state; critical sections
  contain no I/O, no logging, no user callbacks (stated in code comments). Supported
  topology: one producer + one consumer; more producers/consumers remain correct via
  the same lock. Stdlib only (`threading` + `collections.deque`); type hints on all
  public APIs; no bare `except` (no `except` at all in the module — the only raise
  is the documented closed-`put` `RuntimeError`).
- **Counters**: `submitted` (accepted puts incl. drop-causing), `dropped` (discarded
  stale), `depth` property (`0 <= depth <= maxsize`). Both counters monotonic across
  `clear()`/`close()` for later P1-006 telemetry (no telemetry code here).
- **`__repr__` payload-free**: renders only `maxsize/depth/submitted/dropped/closed`.
- **P1-002 minor #4 choice — document-why-silent (zero behavior change)**:
  failed-open cleanup `release()` errors stay discarded so the open-failure
  `last_error` is preserved, while explicit `release()` arms `last_error` on backend
  errors. One policy per path, each now documented with an inline comment plus a
  `release()` docstring note; two new tests pin the alignment.

## 6. Assumptions

- `BaseException`-on-`put`/`get` (e.g. `KeyboardInterrupt` inside `put`) is out of
  scope: the lock is a non-reentrant `threading.Lock` used via context manager, so
  it releases correctly on any unwind; no test pins interpreter-teardown races.
- P1-002 review probes (factory-returns-`None`, `BaseException` propagation) remain
  valid: this task changed no `capture.py` runtime behavior (docstrings, comments,
  annotations only).

## 7. Limitations

- Single-process `threading` design only; no cross-process/async support (not required).
- `depth`/`submitted`/`dropped` properties each take the lock separately — a reader
  sampling all three gets three snapshots, not one atomic triple. The stress
  invariant is asserted post-join (quiescent), so this is test-sound; P1-006
  telemetry should note it if it ever needs an atomic snapshot.
- No eviction callbacks, no `put_nowait` alias, no `maxsize` introspection beyond the
  read-only property — deferred to actual consumers (P1-004+).
