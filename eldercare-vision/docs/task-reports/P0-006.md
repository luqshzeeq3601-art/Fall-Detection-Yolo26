# P0-006 — Structured logging: implementer report

## On-call questions this foundation answers

1. **"Which service/component/camera emitted this error, when, and at what severity?"**
   Every record carries `timestamp` (UTC ISO-8601 `…Z`), `level`, `logger`,
   `service`, `component` (`null` when unbound), plus `camera_id`/`incident_id`
   when bound — so a single JSON line is enough to route an alert without
   call-site repetition.
2. **"Can I filter for a specific lifecycle event (e.g. camera reconnects)?"**
   Yes: per-call `extra={"event": "<dotted.code>"}` (e.g.
   `extra={"event": "camera.online"}`) overrides the default
   `"event.unspecified"`, giving stable greppable event codes.
3. **"Did any log line leak RTSP/postgres credentials or tokens — including
   via `logger.exception`, `%s` args, or `extra={…}`?"**
   No by construction: the formatter routes every message, arg, extra/bound
   value, and exception text through the P0-005 sanitizer (URL userinfo
   stripping + `key=value` masking), plus key-name masking for mapping values,
   and tracebacks are never rendered. Adversarial tests assert raw dummy
   secrets are absent on all paths.

## Assumptions

- Level validation is case-insensitive (`"info"` accepted, normalized to
  `INFO`); anything outside `DEBUG/INFO/WARNING/ERROR/CRITICAL` (or non-string)
  raises `ValueError` naming the bad value and leaves the logger untouched.
- `extra` is always present as a JSON object (possibly `{}`); `camera_id` /
  `incident_id` appear only when non-`None`; `error: {type, message}` appears
  only when `exc_info` carries a real exception (tracebacks never rendered).
- `None`/`bool`/`int`/`float` extra values pass through with JSON types (they
  cannot carry credentials); strings are sanitized; all other objects are
  stringified then sanitized. Non-string bound values are stringified at bind
  time and sanitized again at format time.
- Bare secrets with neither URL-userinfo nor `key=value` shape and no
  sensitive key name are outside what the P0-005 sanitizer can detect; the
  guarantee covers credentialed URLs, `password=/token=`-style pairs, and
  sensitive mapping keys (`token`, `password`, …) on all paths.
- Logger propagation is left at the stdlib default so pytest capture and any
  future root handlers keep working; the idempotency guarantee covers the
  single managed `StreamHandler(stderr)` on the `eldercare` logger.

## Limitations

- Foundation only: no metrics, tracing/OpenTelemetry, MQTT telemetry,
  file/rotation handlers, YAML-config loading, or service wiring (all
  explicitly out of scope per the brief; `config/logging.yaml` is
  documentation-only until a later-phase loader).
- `configure_logging()` must be called (or level defaults to `WARNING` with no
  JSON handler) — service entrypoints wiring it up is a later phase.
- No benchmark numbers or service APIs introduced (none invented).
