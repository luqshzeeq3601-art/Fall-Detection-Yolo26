# P11.7-004 — Task Report: V4 Data Protocol & Split Isolation Governance

## Executive Summary
Task P11.7-004 established the formal data protocol, safety/privacy governance, and split isolation rules for Phase 11.7. Crucially, automated guardrails (`DatasetSplitGuard`) now protect the codebase against cross-split subject leakage and prevent training code from touching held-out test data.

## Key Deliverables
1. **Data Governance & Safety Protocol (`docs/reports/P11.7-004-v4-data-protocol.md`)**:
   - **Safety Directive:** Codified an absolute ban on unsafe unprotected falls; required certified crash mats ($\ge 20$ cm) or non-hazardous simulated falls.
   - **Privacy & Consent:** Mandatory informed consent, PII de-identification, and facial blurring for non-public footage.
   - **Licensing Compliance:** Verified URFD CC-BY-NC-SA-4.0 boundaries and explicitly prohibited treating synthetic UP-Fall stick figure renders or label-derived sequences as deployment evidence.
   - **17-Keypoint Standard:** Codified COCO-compatible keypoint indices and temporal phase boundary schema.
2. **Split Isolation Guard (`src/eldercare/fall_engine/evaluation/split_guard.py`)**:
   - `DatasetSplitGuard`: Enforces schema completeness, subject-disjoint partitions ($\text{Subjects}(S_i) \cap \text{Subjects}(S_j) = \emptyset$), and unique video file SHA-256 hashes.
   - `enforce_training_isolation`: Raises `HoldoutAccessError` whenever training or tuning workflows attempt to ingest `holdout` or `test` partitions.
3. **Automated Verification (`tests/unit/test_v4_data_protocol.py`)**:
   - 4/4 tests passing: schema validation, subject-disjointness enforcement, training isolation, and real URFD manifest partition verification (42 dev records across 6 subjects, 28 test records across 4 subjects, zero subject overlap).
