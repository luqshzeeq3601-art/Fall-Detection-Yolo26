# P0-005 Implementer Report — `.env.example`, secret loading/redaction

## STRIDE-lite threat note

Trust boundary: OS process environment + process memory are trusted;
everything else (logs, exception text, `.env.example`, summaries) is an
untrusted sink. Assets: `POSTGRES_PASSWORD`, `VLM_API_KEY`, RTSP/DB URL
userinfo. Relevant threats and mitigations:

- **Information disclosure (primary risk):** raw credentials reaching logs
  or error text. Mitigated by `redaction.py` (userinfo stripping, token
  masking, mapping redaction, `sanitize_exception_message`) and by
  `Settings.redacted_summary()` / `hide_input_in_errors=True` so even
  `ValidationError` text never echoes secret input values.
- **Tampering:** malformed env (bad port/URL/level, missing required) fails
  closed with `ValidationError`; no silent coercion of garbage (empty
  string is only accepted where empty-means-disabled is documented).
- **Denial of service (config):** fail-fast at import/startup time rather
  than mid-run surprises; validators emit generic messages without
  internals or raw values.
- Spoofing / repudiation / elevation: not applicable to this boundary-only
  task (no auth, no services).

## Assumptions

- `DATABASE_URL` precedence: direct non-empty value wins, else composed
  (documented in module docstring, `.env.example`, and tested both ways).
- Empty-string `DATABASE_URL` counts as unset (falls back to composed).
- RTSP validation accepts any `scheme://host` URL (generic URL check, not
  restricted to `rtsp(s)://`); empty string = disabled.
- `redact_mapping` with a caller-supplied key set redacts exactly that set
  (case-insensitive), replacing the default pattern for that call.
- Missing local `.env` file is silently ignored by pydantic-settings
  (default behavior); tests isolate env via autouse monkeypatch fixture.

## Limitations

- Composed `DATABASE_URL` interpolates user/password raw (no URL-encoding);
  passwords containing `@`/`:`/`/` would parse ambiguously — matches
  `docker-compose.yml` behavior, flagged for a follow-up if needed.
- `redact_*_url` rebuilds host via `hostname` (lowercases, strips IPv6
  brackets); userinfo-free URLs are otherwise byte-stable.
- `sanitize_exception_message` handles URL-userinfo and common
  `key=value`/`key: value` secret patterns; free-form standalone tokens
  with no key context cannot be detected generically.
- No DB/MQTT/API/camera/logging-config integration (per brief, later phases).

## Fix loop (P0-005 review Important 1 + 2, fix subagent)

- Important 1 (`sanitize_exception_message` credential fragment):
  removed `_URL_WITH_USERINFO_PATTERN` (`[^/\s@?#]+`, which truncated at
  `/ ? #` whitespace and missed the match entirely for `a/b`-class
  passwords). Added `_SCHEME_PATTERN` plus strict/permissive host-token
  patterns and `_redact_urls_in_text()`: per `scheme://` occurrence,
  userinfo runs to the last `@` whose trailing whitespace-delimited token
  looks like a host (strict numeric-port first, permissive fallback, then
  last-`@` fail-closed); window ends at the next `scheme://` so separate
  URLs never merge. Note: naive per-token `urlsplit` still truncates at a
  raw `/` in the password (netloc split), so last-`@` authority parsing is
  used instead — strictly stronger and fail-closed. Verified live:
  `rtsp://user:p@ss/word@h:554/s` now yields `rtsp://***@h:554/s`
  (was `rtsp://***@ss/word@h:554/s`); `a/b`, `a?b` now redacted
  (previously no match at all). Known tradeoff: a trailing bare `@host`
  (e.g. an email) after a URL in the same window is consumed into the
  masked userinfo — safe over-masking direction, no leak.
- Important 2 (`redact_mapping` `TypeError` on non-string keys): guarded
  the default branch with `isinstance(key, str)` before
  `_DEFAULT_SENSITIVE_PATTERN.search(key)`; non-string keys pass through
  with values untouched, sensitive string keys still masked. Verified live:
  `redact_mapping({1: 'x', 'password': 'y'})` no longer throws.
- New tests (`tests/unit/test_redaction.py`, +6 cases / 2 functions):
