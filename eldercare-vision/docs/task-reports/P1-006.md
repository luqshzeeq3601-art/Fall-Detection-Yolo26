# P1-006 — Capture telemetry: implementer report

## On-call questions (observability skill step 1) → snapshot answers

Written BEFORE instrumenting; every signal below maps to one question:

1. **What capture FPS is this camera actually delivering right now?**
   → `capture_fps` (trailing 5 s window, strict-`>` boundary). `None` = unknown,
   never a fabricated rate.
2. **Is the capture queue saturated?**
   → `queue_depth` (USE saturation), `queue_dropped` + `queue_submitted` (errors).
3. **Is the stream healthy — when was the last frame, how long silent?**
   → `health_state`, `last_frame_at`, `seconds_since_last_frame`.
4. **How many reconnect attempts / consecutive failures have occurred?**
   → `reconnect_attempts`, `reconnect_failures` (mirrors the controller's
   consecutive counter).

CONSTRAINTS.md §11 mapping (capture-side subset): capture FPS → `capture_fps`;
queue depth → `queue_depth`; dropped frames → `queue_dropped`; reconnect count
→ `reconnect_attempts` (+ consecutive `reconnect_failures`). Processed FPS is
explicitly later work, not here. Cardinality is bounded by construction: fixed
field set, no per-frame/per-user labels (camera_id only).

## Ownership map

Telemetry OWNS only: frame-timestamp deque + `frames_received` counter.
Everything else is read LIVE via public getters at snapshot time, never stored:

| Snapshot field | Source (read-only) |
|---|---|
| `queue_submitted/dropped/depth` | `LatestFrameQueue.submitted/dropped/depth` |
| `health_state` / `last_frame_at` | `StreamHealthMonitor.state.value` / `.last_frame_at` |
| `reconnect_attempts` / `reconnect_failures` | `ReconnectController.attempts` / `.consecutive_failures` |
| `capture_fps` / `frames_received` | owned deque + counter |

Lock rule: telemetry lock guards owned deque/counter ONLY; component getters
are called WITHOUT holding it (acquire-copy-release, then assemble). No I/O,
logging, or callbacks in any critical section. `snapshot()` is side-effect-free
(pruning happens in `note_frame()` only; repeated snapshots are identical).

## logger.py decision: DEFER (untouched) + reasoning

**Decision: do NOT touch `src/eldercare/common/logger.py`** (`git diff` empty).

1. No direct telemetry requirement exists: `telemetry.py` performs zero logging
   (no logger import, no I/O) — it never emits through `logger.py`, so neither
   deferred minor (raw `record.name`, unguarded `json.dumps`) can affect it.
2. The brief's MUST is snapshot strict-JSON-safety, which is guaranteed by
   construction inside telemetry (finite floats only: `count >= 2` over finite
   `window > 0`; `None`s preserved) and proven by `allow_nan=False` round-trips
   on empty/populated/post-prune/capped snapshots — no logger change needed.
3. Any logger.py edit would therefore fail the relevance rule's "directly
   required" prong regardless of size. The P0-006 minors stay deferred for
   their owning task. No behavior change, no diff.

## Assumptions

- `seconds_since_last_frame` is `None` when no frame was ever recorded (no last
  frame → unknown, not zero), rather than the monitor's since-creation silence.
- `snapshot(now=...)` validates explicit timestamps like `health.poll` (fail
  fast over emitting NaN); clock-sourced values go through the same check.
- `fps_window_seconds=inf` rejected (non-finite): an infinite window would pin
  fps ≈ 0.0, a fabricated-looking rate; brief requires finite `> 0` semantics.
- `frame_window_size` is the SOLE internals accessor (documented hook for the
  memory-cap test); bool/non-numeric timestamps rejected like health.
- Out-of-order notes are accept-and-prune (observations ≠ state); snapshot scans
  the full deque (no sortedness assumption).

## Limitations

- FPS resolution is window-quantized (5 s default); bursts shorter than the
  window are smoothed — honest aggregate, not per-second truth.
- A stalled clock disables window pruning; memory is then bounded ONLY by the
  16384-entry cap (documented trade-off, tested at 100k notes).
- Dual-clock skew (telemetry clock vs health clock) can yield small/negative
  `seconds_since_last_frame`; reported honestly, never clamped.
- No Prometheus/OTel/MQTT/DB/hardware/dashboard/Phase-2 code (forbidden scope).
