## Purpose
Lock down the YOLO26s-Pose contracts established by P2-002 through P2-005 with a compact, deterministic, CPU-safe regression layer so future changes cannot silently break inference shapes, keypoint alignment, confidence preservation, normalized outputs, or timing behavior. This is a TEST-ONLY task: pin cross-module behavior that the existing isolated unit tests do not protect, without duplicating them and without changing production code.

- Regression coverage (each area at least one test, cross-module wherever the wiring allows):
  1. Production reference: code defaults match the P2-002 verified record — `UltralyticsPosePredictor` defaults (`model_name="yolo26s-pose.pt"`, `device=0`, `imgsz=640`) equal the CONSTRAINTS §2 / verify-script call pattern; `KEYPOINT_COUNT == 17` and `KEYPOINT_NAMES` full-tuple equality (COCO order, AI_SPEC §4); `GOLDEN_4P` stub shapes equal `(4,17,2)`/`(4,17)` (the exact P2-002 acceptance shapes). No model run, no download — defaults and shapes only.
  2. Golden 4-person end-to-end: `GOLDEN_4P` → `adapt_pose_results` → 4 `PersonPose` in order, dims `(810, 1080)` from `orig_shape=(1080, 810)` (h→w normalization pinned), per-person bbox + detection conf bit-for-bit, all 17 keypoint coords + confs bit-for-bit for at least the first and last person.
  3. Zero/one-person cross-module: stub → adapter → `PosePipeline.process_frame` (fake predictor + programmed `FakeTimer`) → `PosePipelineResult`: `persons == ()` with dims kept (zero); exact bbox/conf/coords (one); timing present with exact ms values on the same run (proves timing rides along without disturbing pose).
  4. Confidence preservation incl. `0.0` and low values: golden confs containing exact `0.0` and small values (e.g. `1e-6`-scale) survive adapter + pipeline bit-for-bit (`==`, not approx).
  5. Missingness: NaN/`±Inf` coords in the golden fixture → `present=False`, coords `None`, conf preserved; present siblings untouched — asserted on the PIPELINE result (not just the adapter), proving no fabrication across the wiring.
  6. Fail-closed spot-checks at integrated level: keypoint dim ≠ 17 and boxes/person count mismatch through `process_frame` → `ValueError` each (no exhaustive malformed matrix — unit suites own it; regression pins that the pipeline still fails closed end-to-end).
  7. `orig_shape` normalization: `(h, w)` → `(width, height)` pinned via GOLDEN dims plus one non-square second shape (e.g. `(480, 640)` → `(640, 480)`).
  8. Timing non-interference: same golden input through default-timer vs programmed-timer pipelines → identical `pose`/`camera_id`/`frame_id`/`capture_timestamp` fields (timing values may differ; everything else bit-identical).
  9. Determinism: two identical `process_frame` calls (same frame object, fresh programmed timers or same-stamp timers) → equal `pose` trees (dataclass `==` on `PoseFrame`, covering persons/bboxes/keypoints/confs).
  10. Framework independence: `sys.modules` introduces none of `torch`/`ultralytics`/`cv2` across a full golden-matrix run (0/1/4-person adapter + pipeline + timing); source-level assertion that `adapter.py` + `timing.py` contain no such imports (read the files, assert no import-statement match — pins the boundary in CI).
  11. Manual-path separation: `scripts/dev/verify_pose_model.py` exists (the preserved real-model/GPU validation path) AND is not collected by pytest (assert its path is outside `tests/` and it imports no pytest) — pins that CPU CI never depends on the GPU/download path. Do NOT execute the script.
