# P3-005 — Multi-person / occlusion tracking validation

## Purpose
Prove that multiple tracked people and temporary occlusions cause zero cross-person state leakage, history contamination, or identity reassignment across the P3-001…P3-004 stack. This is a TEST-ONLY task: pin cross-key/cross-frame isolation that the existing single-key unit suites do not cover, without duplicating them and without changing production code.

## Requirements
- New tests ONLY (plus brief + report). **DO NOT MODIFY any `src/` file.** If (and only if) a genuine isolation defect is found — i.e. a scenario exposes behavior contradicting a P3-001…P3-004 acceptance record — STOP, document the defect with file:line + evidence in the report, and leave the code untouched (the Coordinator decides; the one blocking-escalation path, not a license to refactor).
- Deterministic CPU-safe scripted fake backends (the `TrackBackend` surface); NEVER import `ultralytics`/`torch`/`cv2` in tests; zero sleeps/network/GPU/downloads; `sys.modules` + AST framework-freedom proofs.
- Core invariant under test (every scenario serves it): project domain state is ALWAYS keyed by `(camera_id, track_id)` and NEVER infers identity from person array position, bbox ordering, or pose ordering.
- Scenario coverage (each area at least one test, cross-key/cross-frame wherever the wiring allows):
  1. Two+ people tracked simultaneously with independent histories (per-key snapshots contain exactly their own observations, bit-exact).
  2. People crossing / moving close together (bboxes approach/overlap across frames; histories still follow backend IDs, never merge or swap).
  3. One person temporarily disappears (backend returns fewer IDs): survivor's history continues uninterrupted; no placeholder/fabricated entry for the missing person.
  4. One visible + one missing across several frames, then return with the SAME backend ID → continuity (single unbroken key history, gap visible as timestamp jump, no merge).
  5. Return with a DIFFERENT backend ID → new identity: old key retains exactly its pre-gap history (unchanged), new key starts fresh (no ghost observations, no merge).
  6. `track_id=None` never contaminates: frames mixing `(id, None)` leave the ID'd key with only its own observations and create no `None` key; `None`-carrying observations never appear in any history.
  7. Same numeric `track_id` on different cameras stays isolated (both directions).
  8. Expiring one track leaves all other keys bit-exact (snapshots + ordering intact); removed key recreates fresh on next append.
  9. Zero-person frames preserve all unrelated active state (histories untouched, backend consulted per P3-001 policy).
  10. Person ORDER SWAPS across frames with IDs following content (frame1 `[A,B]→[1,2]`, frame2 `[B',A']→[2,1]`): histories keyed `[1: A,A']`, `[2: B,B']` — proves identity follows backend IDs, never list position. Include at least one adversarial reorder (reverse + rotation across 3 frames).
  11. Occlusion gaps do not silently merge identities: after a gap, an observation lands ONLY in the key whose ID the backend returned (assert the other key's history is byte-identical pre/post gap).
  12. Determinism: two identical full sequences (fresh stores/backends) → equal snapshots for every key.
  13. Data attachment: every history entry's bbox/keypoints/confs belong to the correct person (per-entry content assertions, incl. exact `0.0`/tiny confs and a missing-keypoint person, proving no content swap alongside ID correctness).
- Integration-style sequence (in the integration file): `PoseFrame` sequence (≥4 frames, incl. a 2-person cross + 1-person gap + reorder) → scripted fake ByteTrack IDs → `tracked_frame_to_observations` → `TrackHistory.append` (+ one `expire_stale` pass) → per-key snapshots proving identity isolation end to end, consumable without tracker knowledge.
- Compactness (hard): NO MORE than 30 tests total. Each test must pin ISOLATION across keys/frames/cameras; re-asserting single-key behavior already pinned by P3-001…P3-004 suites is bloat — the Reviewer is instructed to flag duplication bloat as Important. Target ~20–26 tests.
- Suggested split (implementer may adjust within the cap): `tests/unit/test_multi_person_isolation.py` (isolation unit scenarios via tracker+converter+history directly) + `tests/integration/test_occlusion_sequences.py` (scripted multi-frame sequences incl. the end-to-end chain). Basenames are unique repo-wide — NO `__init__.py` additions.
- Report must contain a scenario→test map, a non-duplication statement (what single-key coverage was deliberately not re-asserted), RED→GREEN evidence, command log, regression proof, assumptions.
