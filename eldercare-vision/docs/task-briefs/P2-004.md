# P2-004 — Integrate pose into live pipeline

## Purpose
Implement the first end-to-end Phase 2 vision pipeline integration: latest-frame/stream input → YOLO26s-Pose inference → `adapt_pose_results()` → normalized `PoseFrame` output. Reuse the existing Phase 1 stream abstractions rather than duplicating capture logic. Keep the inference boundary clean and testable so CPU CI can use fake model/capture objects without requiring CUDA or downloading weights. Satisfy the P1-007 gate precondition (first fake-capture end-to-end test through the real queue/health/telemetry components) inside the pose end-to-end proof.

## Requirements
- New module `src/eldercare/vision/pose/inference.py` (the ONLY Phase 2 file allowed to touch Ultralytics; numpy + stdlib otherwise):
  - `PosePredictor` Protocol: `def predict(self, image: Any) -> Any` returning a single duck-typed Ultralytics `Results` (with `keypoints`/`boxes`/`orig_shape` as consumed by `adapt_pose_results`). Document that fakes implement this surface.
  - `UltralyticsPosePredictor` production class: `__init__(model_name: str = "yolo26s-pose.pt", device: int = 0, imgsz: int = 640)` per `CONSTRAINTS.md` §2 defaults; `predict(image)` lazily imports `ultralytics` INSIDE the method (never at module top level so CPU CI collection never requires CUDA/weights), loads `YOLO(model_name)` once, calls `predict(source=image, device=device, imgsz=imgsz, verbose=False)[0]`, returns the single `Results`. No thresholding, no adaptation, no `Results` retention beyond the return. Docstring cites the P2-002 acceptance record (`xy=(N,17,2)` / `conf=(N,17)` / `cuda:0`, `bus.jpg` 4 persons) as the production contract. Fail closed on empty result lists (`ValueError`).
  - No `torch`/`cv2` import in this file. No inference at import time. No threads.
- New module `src/eldercare/vision/pose/pipeline.py` (stdlib + numpy ONLY — NO `ultralytics`/`torch`/`cv2` import at all, not even lazily; grep-proof):
  - `SourceFrame` frozen dataclass: `camera_id: str` (non-empty; pattern validation lives upstream in `CameraConfig` — this layer only requires non-empty string), `frame_id: int` (`>= 0`, `operator.index`, bool-rejected), `capture_timestamp: float` (finite, `>= 0`), `image: numpy.ndarray` (3-D `H×W×C`, `dtype` uint8-equivalent shape check only — no pixel-value policy). Documents the ARCHITECTURE §5 frame-observation mapping (`camera_id`/`frame_id`/`capture_timestamp` + `image`; `decode_timestamp` is the pipeline-entry instant and need not be a separate field — record this decision).
  - `PosePipelineResult` frozen dataclass: `camera_id: str`, `frame_id: int`, `capture_timestamp: float`, `pose: PoseFrame` (the normalized 17-keypoint contract from P2-003). No `Results`, no image, no URL stored.
  - `PosePipeline` class: `__init__(camera_id: str, predictor: PosePredictor, clock: Callable[[], float] = time.monotonic)` — owns NO capture/queue/health/telemetry (they are passed per-call, read-only). Methods (minimal, synchronous, no threads spawned):
    - `process_frame(frame: SourceFrame) -> PosePipelineResult`: calls `predictor.predict(frame.image)` → `adapt_pose_results(results)` → wraps with propagated `camera_id`/`frame_id`/`capture_timestamp`. Cross-checks `results.orig_shape (h, w)` against `frame.image.shape[0:2]`; mismatch → `ValueError` naming both (fail clearly on malformed inference results). Drops the `Results` reference immediately after adaptation (local only, `del`; never stored on `self`). Malformed `Results` → the adapter's `ValueError` propagates unwrapped except for adding frame context via `raise ... from` (never fabricate, never return empty on error). Logs one structured record per processed frame at DEBUG/INFO with `camera_id`/`frame_id`/person-count only (no URLs, no pixel data, via `eldercare.common.logger`).
    - `process_capture_read(ok: bool, frame_image: Any | None, frame_id: int, capture_timestamp: float | None = None) -> PosePipelineResult | None`: `ok is False` or `frame_image is None` → `None` (read failure is not a pose — never fabricate; caller drives reconnect/health). Otherwise builds a `SourceFrame` with this pipeline's `camera_id` and delegates to `process_frame`. `capture_timestamp=None` reads the injected `clock()`.
    - `process_queued_frame(queue: LatestFrameQueue, frame_id: int, capture_timestamp: float | None = None) -> PosePipelineResult | None`: `queue.get()` returning `None` → `None` (empty queue is not an error). Otherwise treats the popped payload as the frame image (payloads are opaque `np.ndarray` frames in this integration) and delegates via `process_capture_read(True, payload, ...)`. Reads the queue through its public `get()` only; never touches internals.
  - Locking/threading: pipeline holds no lock and spawns no threads (single capture-loop thread owns the call sequence per P1-007 §1; thread-safe handoff remains the queue). Document this.
  - `__repr__` carries `camera_id` only (no URLs, no images, no model internals).
- Reuse, don't duplicate: the pipeline accepts `RtspCapture`-compatible reads (`(ok, image)` tuples as returned by `RtspCapture.read`) and `LatestFrameQueue` payloads via the methods above; it imports stream types for typing ONLY under `TYPE_CHECKING` (zero runtime import cost, no behavior change to `vision/stream/*`). Do NOT reimplement capture/open/retry/queue/health/telemetry logic. Do NOT create a threaded manager loop (no `manager.py`, no background threads — that remains future wiring; this task proves the synchronous data path).
- Required behavior (tested):
  - zero-person `Results` (`keypoints is None`) → `persons == ()` with image dims preserved from `orig_shape`.
  - multi-person (≥2) ordering + per-person detection confidences preserved bit-for-bit.
  - frame dimensions preserved (`PoseFrame.image_width/height == orig_shape (w, h) == input image (w, h)` when fakes are consistent).
  - pose confidences preserved (adapter guarantee; pipeline asserts bit-for-bit on at least one keypoint + one detection conf in tests).
  - timestamps/source identity propagated (`camera_id`/`frame_id`/`capture_timestamp` from `SourceFrame` into the result, exact equality).
  - malformed inference results fail clearly (`ValueError` naming the defect: `results=None`, bad dims, `orig_shape`/image shape mismatch, adapter-level defects propagate).
  - no heavyweight `Results` retention (pipeline instance holds no `Results` attribute; `vars(pipeline)` contains no `Results`; grep-proof that `pipeline.py` never names a `Results` store).
  - CUDA/model-specific code isolated (only `inference.py` mentions `ultralytics`, lazily; `pipeline.py` + all tests import neither `ultralytics` nor `torch` nor `cv2` at runtime — `sys.modules` + grep proofs).
- P1-007 precondition satisfied HERE (not a new Phase 1 task): the integration test must pump a fake capture end-to-end through the REAL `LatestFrameQueue` + `StreamHealthMonitor` (fake clock) + `CaptureTelemetry` (fake clock) fan-in (`queue.put` handoff, `health.notify_frame` driver, `telemetry.note_frame` fan-in) with exact `submitted`/`dropped`/`depth`, health `UNKNOWN → ONLINE` transition, and fps-shape assertions, THEN run the queued payload through the fake predictor + adapter to the normalized 17-keypoint contract. This is the gate-required wiring proof, done synchronously with fakes (no threads, no network, no sleeps).
- Tests (TDD, RED first; CPU-only numpy/list stubs — NEVER import `ultralytics`/`torch`/`cv2` in tests; assert `sys.modules` introduces none of them after pipeline calls):
  - `tests/unit/test_pose_pipeline.py`: `SourceFrame`/`PosePipelineResult` validation (bad `camera_id`/`frame_id`/timestamp/image → `ValueError`/`TypeError`); `process_frame` zero-person dims-kept; one-person exact values incl. conf bit-for-bit (numpy + list-stub `Results` variants); multi-person (3) ordering + per-person conf; missing-keypoint passthrough (`present=False`, coords `None`, conf preserved — via non-finite stub coords); malformed matrix (`results=None`, bad dims, `orig_shape`/image mismatch, adapter defects e.g. 16 kpts / boxes mismatch / NaN conf → `ValueError` each); `process_capture_read(False/None)` → `None` (never fabricates); `process_queued_frame` empty → `None`, populated → result with propagated ids; no-retention (`vars(pipeline)` has no `Results`; double-call leaves no growth); framework-freedom (`sys.modules` introduces none of `torch`/`ultralytics`/`cv2`; pure-list stubs work); `camera_id` mismatch (`SourceFrame` with different id than pipeline → `ValueError`, proving identity is not silently overwritten).
  - `tests/integration/test_pose_pipeline.py` (FIRST integration test; gate-required e2e): fake `VideoCaptureLike` returning one synthetic `np.zeros((480, 640, 3), dtype=np.uint8)` frame with `(True, frame)` then `(False, None)`; real `LatestFrameQueue(maxsize=2)` + real `StreamHealthMonitor(camera_id, clock=fake)` + real `CaptureTelemetry(camera_id, queue, health, None, clock=fake)`; sequence `capture.read → queue.put → health.notify_frame → telemetry.note_frame → pipeline.process_queued_frame → fake predictor (stub `Results` with `orig_shape=(480, 640)`, 1 person, known 17 kpts) → PoseFrame`; assert queue `submitted/dropped/depth` exact, health transition `UNKNOWN → ONLINE` + state `ONLINE`, telemetry `frames_received == 1` + snapshot shape, pose `persons == 1`, 17 keypoints, dims `(640, 480)`, detection conf exact, `camera_id`/`frame_id`/`capture_timestamp` propagated exact; plus a zero-person e2e variant (`keypoints=None` → `persons == ()`). Deterministic fake clocks only (zero real sleeps).
- Contract-first: `pipeline.py` docstring documents the data path (`SourceFrame → PosePredictor.predict → adapt_pose_results → PosePipelineResult`), the `orig_shape`-vs-image cross-check, the no-retention rule, the threading ownership note, and the Phase 3 handoff (track observation consumes `pose.persons[i].keypoints` + confidences + `bbox_xyxy`; no track IDs here).
