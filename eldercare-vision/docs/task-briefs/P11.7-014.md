# Task Brief: P11.7-014 — Pipeline Integration, ADR-009, and Model Freeze

## 1. Context & Objectives
To prepare for unbiased, leak-free evaluation on the held-out test split (`subj-07` through `subj-10`), all architectural components must be unified into an end-to-end inference engine (`FallEnginePipelineV4`), formally documented in an Architectural Decision Record (`ADR-009`), and immutably locked via a cryptographic model freeze manifest (`models/v4_freeze_manifest.json`).

---

## 2. Technical Scope
- **`src/eldercare/fall_engine/pipeline_v4.py` (`FallEnginePipelineV4`):**
  - Unifies multi-scale temporal windowing (`MultiScaleTemporalFeatures`), camera perspective normalizer (`CameraPerspectiveNormalizer`), recurrent temporal classifier (`GRUClassifierV4`), complex ADL false-alert suppressor (`ADLFalseAlertSuppressor`), and per-track state machines (`TrackFallStateMachineV3`).
  - Implements observation history buffering, keypoint de-warping, frame-batch dispatch, and multi-track lifecycle management.
- **`docs/adr/ADR-009-phase-11-7-v4-deployment-hardening.md`:**
  - Formal architectural record specifying decision rationale, trade-offs, multi-stage defense architecture, and model freeze commitments.
- **`scripts/calibration/freeze_v4_pipeline.py` & `models/v4_freeze_manifest.json`:**
  - Hashes all 9 core artifacts (classifier JSON, calibrated YAML, dataset manifests, feature caches, pipeline code) to guarantee freeze immutability before touching held-out test evaluation.
- **Verification:**
  - Comprehensive unit test suite (`tests/unit/test_v4_e2e_pipeline.py`) validating defaults, standing tracks, ADL suppression e2e, multi-person processing, track cleanup, and manifest cryptographic integrity.
