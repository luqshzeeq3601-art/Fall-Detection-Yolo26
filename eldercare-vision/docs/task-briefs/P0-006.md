# P0-006 — Structured logging

## Purpose
Establish the structured-logging foundation every service will use: JSON log records with stable fields, secret-safe output via the P0-005 redaction utilities, configurable levels, and idempotent setup. Foundation only — no metrics, tracing, or telemetry transport.

## Requirements
- New module `src/eldercare/common/logger.py` (NOT `logging.py` — avoid shadowing the stdlib name). Stdlib `logging` only; no new dependencies.
  - `configure_logging(level: str = "INFO") -> logging.Logger` (root `eldercare` logger): validates the level string (invalid → `ValueError` naming the bad value), attaches exactly one `StreamHandler(stderr)` with the JSON formatter, and is IDEMPOTENT — repeated calls never add duplicate handlers (reconfigure in place: update level/formatter on the existing handler).
  - `get_logger(service: str, component: str | None = None, **bound: str) -> logging.LoggerAdapter` (or equivalent wrapper): binds `service` (+ optional `component` and string extras such as `camera_id`) so every record carries them without call-site repetition. Non-string bound values must be stringified safely, never logged raw.
  - `JsonFormatter(logging.Formatter)`: emits one JSON object per line with EXACT stable keys: `timestamp` (UTC ISO-8601, `…Z`), `level`, `logger` (logger name), `service`, `component` (null when unbound), `event` (event code, default `"event.unspecified"`), `message`, plus optional `camera_id` / `incident_id` only when present, plus an `extra` object for any other caller fields. `exc_info` exceptions serialize as `error: {type, message}` with the message sanitized (never raw).
  - Secret safety is STRUCTURAL, not advisory: the formatter/filter layer routes every message, arg, extra value, and exception text through P0-005 `sanitize_exception_message` (reuse by import — do NOT reimplement redaction). A credentialed RTSP/postgres URL, token, or `password=…` pair must be physically incapable of reaching the output stream unredacted, including via `logger.exception`, `extra={…}`, and `%s`-style args.
  - No `print()` in `src/` library code: add ruff `T201` (flake8-print) to the `select` list in `pyproject.toml` (config-only change; verify the existing tree stays clean).
- `config/logging.yaml`: correct the stale skeleton (it names the wrong phase) and document the ACTUAL implemented knobs: `level`, `format: json`, `stream: stderr`, `redaction: always-on (P0-005)`, `event` naming rule. No YAML parsing in code yet (loader is a later-phase integration — state this in a comment, do not add pyyaml).
- Tests (TDD, RED first): `tests/unit/test_logging.py` covering at minimum:
  1. emitted line parses as JSON with all stable keys (`timestamp/level/logger/service/component/event/message`);
  2. `timestamp` is UTC ISO-8601 ending in `Z`; `level` matches the call;
  3. bound `service/component/camera_id/incident_id` appear on every record from that logger; unbound `component` is null;
  4. `event` code override per call (`extra={"event": "camera.online"}` or explicit kwarg — pick one API, document it);
  5. level filtering: `debug` suppressed at `INFO`, shown at `DEBUG`; invalid level string → `ValueError`;
  6. idempotency: `configure_logging` ×3 → exactly one handler, no duplicated lines (caplog/capture assertion);
  7. adversarial secrets through ALL paths — message, `%s` args, `extra` mapping, `logger.exception` with credentialed URL in the exception — assert raw password/token absent from captured output (reuse adversarial values style from P0-005);
  8. `exc_info` renders as sanitized `error: {type, message}` with no traceback-secret leak;
  9. no-`print` guard passes on `src/` (via ruff T201 gate, asserted by `ruff check` in the gate run, not a pytest test).
- `LOG_LEVEL` wiring: `configure_logging` accepts a plain string so later phases can pass `settings.log_level` directly; do NOT import settings inside logger.py (keep the dependency direction logger ← settings, not the reverse — no import cycle).
