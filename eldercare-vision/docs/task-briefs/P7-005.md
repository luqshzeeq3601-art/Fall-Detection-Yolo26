# P7-005 — Broker outage/recovery

## Task row
`TASK_SKILL_MATRIX.md` Phase 7: P7-005 Broker outage/recovery — Superpowers
`systematic-debugging`, `verification-before-completion` — Owner TEST+OPS —
Done when detector continues.

## Requirements (authoritative)
- `ARCHITECTURE.md` §7: MQTT unavailable → queue/drop per policy, detector
  continues; core incident path never depends on broker ack.
- Goal rules: bounded reconnect/backoff, no busy loops, injectable timing
  (no real sleeps in unit tests), clean shutdown, no duplicate
  subscriptions/publish loops after reconnect, outages never crash core
  processing, duplicate-delivery considered (QoS 1 = at-least-once).

## Scope
- `mqtt/resilience.py` (new): frozen `PublishOutcome` (delivered/reason/
  topic/event_id); `publish_best_effort()` + `publish_metrics_best_effort()`
  (never raise — catch `TransportError` AND broad `Exception`, input
  validation errors included); pure `ReconnectPolicy` (`delay_for()` bounded
  exponential, `max_attempts` cap, validated); `connect_with_retry()`
  with injectable `sleeper` (disconnect-before-retry, exact attempt budget,
  True/False result).
- Duplicate-delivery: stable `event_id` across retries (consumer-dedupable);
  no publish loops (one transport call per API call, test-proven).
- Tests: `tests/unit/test_mqtt_outage.py` — best-effort never raises,
  detector outputs intact through outage, recovery delivers, retry schedule
  bounded/exponential with fake sleeper (wall-time ~0), exhaustion budget,
  duplicate same-id/no-storm, clean shutdown.

## Out of scope
- Live-broker integration (unit CI stays broker-free); consumer-side
  malformed handling already covered by P7-002 envelope tests.
