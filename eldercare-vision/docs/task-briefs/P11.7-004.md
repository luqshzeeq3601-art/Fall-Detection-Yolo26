# P11.7-004 — Task Brief: V4 Data Protocol & Split Isolation Governance

## Objective
Establish stringent data governance, safety, privacy, annotation, and split isolation rules for V4:
1. Formalize human participant informed consent, PII de-identification, and mandatory safety crash mat directives.
2. Establish legal licensing boundaries (URFD CC-BY-NC-SA-4.0) and enforce the complete ban on synthetic renders as real evidence.
3. Define the COCO-compatible 17-keypoint and frame-indexed fall event annotation contract.
4. Implement automated split verification (`DatasetSplitGuard`) enforcing zero subject overlap and programmatic holdout isolation.

## Scope
- `docs/reports/P11.7-004-v4-data-protocol.md`: Formal specification of data protocol, privacy, licensing, annotation schema, and split governance.
- `src/eldercare/fall_engine/evaluation/split_guard.py`: `DatasetSplitGuard`, `SplitLeakageError`, `HoldoutAccessError`.
- `src/eldercare/fall_engine/evaluation/__init__.py`: Module exports.
- `tests/unit/test_v4_data_protocol.py`: Test suite verifying schema validation, disjoint partitions, duplicate hash rejection, training isolation, and real URFD manifest integrity.

## Acceptance Criteria
1. Explicit informed consent and participant physical safety directives codified (no unprotected falls).
2. Synthetic stick-figure renders and label-derived data permanently barred from real deployment status.
3. 17-keypoint standard and temporal phase annotation schema specified.
4. Programmatic split guard prevents data leakage and blocks training code from accessing holdout data.
5. All code clean under `ruff check` and `ruff format --check`.
6. Independent review approval with 0 Critical / 0 Important findings.
