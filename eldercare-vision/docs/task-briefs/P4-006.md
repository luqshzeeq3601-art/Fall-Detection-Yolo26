# P4-006 — Cache Derived Keypoints: Task Brief

## 1. Objective
Implement a structured, provenance-tracked keypoint caching mechanism for accelerated development, threshold calibration, and sequence evaluation experiments per `DATASET_PLAN.md` §9 & §11, `METHODOLOGY.md`, `TASK_SKILL_MATRIX.md`, and `AI_SPEC.md`.

## 2. Requirements & Specifications
- **Provenance Tracking (`DATASET_PLAN.md` §9)**:
  - Every cached sequence file MUST include:
    - `source_sample_id`: Identifier of the source sequence/video
    - `model_name`: Detection model used (e.g., `yolo26s-pose.pt`)
    - `inference_library_version`: Version of Ultralytics/inference framework
    - `inference_config`: Dictionary containing inference settings (`imgsz`, `conf`, `tracker`, etc.)
    - `extraction_timestamp`: ISO 8601 UTC timestamp
    - `source_checksum`: SHA-256 hash or checksum of the source video/stream where available
    - `fps`: Capture frame rate
    - `total_frames`: Number of frames in the sequence
    - `schema_version`: Cache serialization format version (e.g. `1.0`)
    - `is_derived`: Must be `True`
    - `is_ground_truth`: Must be `False` (guarding against pseudo-keypoint label leakage)
- **Data Payload**:
  - Sequence of frames containing:
    - `frame_index`: Integer frame index
    - `timestamp`: Capture timestamp in seconds
    - `image_width` and `image_height`: Positive integer dimensions
    - `persons`: Sequence of detected/tracked persons with:
      - `track_id`: Integer track ID or `None`
      - `bbox_xyxy`: 4-tuple of floats `(x1, y1, x2, y2)`
      - `detection_confidence`: Float in `[0, 1]`
      - `keypoints`: Exactly 17 `Keypoint` objects with coordinates, confidence, and `present` flag
- **Bidirectional Conversion**:
  - Seamless conversion to and from `TrackObservation` sequences and `TrackedFrame` sequences.
- **Serialization & Storage**:
  - Deterministic JSON serializer and deserializer with fail-closed schema validation.
  - Safe disk storage with atomic write semantics and gzip compression support.
  - Verification utilities for cache provenance and integrity checks.

## 3. Implementation Targets
- `src/eldercare/fall_engine/cache/schema.py`: Dataclasses and validation for metadata, persons, frames, and sequences.
- `src/eldercare/fall_engine/cache/serialization.py`: JSON serialization/deserialization and bidirectional conversion with domain contracts.
- `src/eldercare/fall_engine/cache/storage.py`: Atomic disk I/O, hash verification, and provenance checking.
- `src/eldercare/fall_engine/cache/__init__.py`: Package exports.
- Export in `src/eldercare/fall_engine/__init__.py`.

## 4. Verification Plan
- Unit tests: Metadata validation, schema bounds, keypoint invariant checks, JSON serialization/deserialization round-tripping, corrupt/tampered file rejection, non-ground-truth enforcement.
- Integration tests: End-to-end caching of synthetic fall sequences, loading cached sequences into `SequenceEvaluationRunner` and `FallStateMachineManager`, verifying identical metrics.
- Ruff check and format.
