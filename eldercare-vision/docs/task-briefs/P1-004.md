# P1-004 — Stall/health state machine

## Purpose
Implement the deterministic camera stall/health state machine (`UNKNOWN → ONLINE ⇄ DEGRADED ⇄ OFFLINE`) driven by frame arrivals and silence timeouts on an injectable clock. Pure logic — no OpenCV, no threads spawned, no reconnect.

## Requirements
- New module `src/eldercare/vision/stream/health.py` (stdlib only: `threading`, `time`, `enum`, `dataclasses`; type hints on all public APIs; no bare `except`):
  - `CameraHealthState(str, Enum)`: `UNKNOWN`, `ONLINE`, `DEGRADED`, `OFFLINE` (string values lowercase for future JSON/event use: `"unknown"`, `"online"`, `"degraded"`, `"offline"`).
  - `HealthTransition` frozen dataclass: `from_state`, `to_state`, `reason: str`, `timestamp: float`. Reasons as module constants: `REASON_FRAME_RECEIVED`, `REASON_SILENCE_DEGRADED`, `REASON_SILENCE_OFFLINE`, `REASON_INITIALIZED`? (no init transition emitted — initial state is just `UNKNOWN`; keep the constant set to the three real causes).
  - `StreamHealthMonitor`:
    - `__init__(camera_id: str, degraded_after: float = 2.0, offline_after: float = 10.0, clock: Callable[[], float] = time.monotonic)`: validate `0 < degraded_after < offline_after` else `ValueError` naming the violated relation; `camera_id` non-empty (reuse the P1-001 allowlist? — accept plain non-empty string here; the CameraConfig already guarantees shape upstream; document this layering). `clock` injected for determinism (default real monotonic).
    - `notify_frame(timestamp: float) -> HealthTransition | None`: records `last_frame_at`; returns a transition to `ONLINE` (reason frame-received) ONLY if previous state != `ONLINE`, else `None` (no duplicate emissions). Timestamp rules: must be finite and `>= 0` else `ValueError`; timestamps OLDER than `last_frame_at` (out-of-order) are IGNORED (return `None`, state unchanged — document + test; clocks can jitter).
    - `poll(now: float | None = None) -> HealthTransition | None` (`now=None` → `clock()`): evaluates silence `now - last_frame_at` (or since creation when no frame ever arrived — from `UNKNOWN`, prolonged pre-first-frame silence must ALSO degrade/offline the monitor; document + test): silence `> offline_after` → `OFFLINE` (reason silence-offline); elif silence `> degraded_after` → `DEGRADED` (reason silence-degraded); else `None`. Returns a transition ONLY on state change, else `None`. `now` validated like frame timestamps (`ValueError` on non-finite/negative).
    - Boundary semantics (contract-first, tested both sides): transitions fire on STRICTLY-greater (`>`); exact-equality stays (`silence == threshold` → no transition). Document in docstring.
    - Thread-safety: single `threading.Lock` around all state (same pattern as the queue; may be called from capture and consumer threads). No I/O inside the lock.
    - Read-only introspection: `state`, `last_frame_at: float | None`, `silence(now=None) -> float | None` (None when no frame yet — or since-creation? decide: `silence` measures since last frame; when never, since creation using clock; document). `__repr__`: `camera_id/state/silence` — no URLs exist in this module by construction (assert in test via no-URL scan of repr).
    - Minimal transition logging (P0-006 reuse, bound `service="vision"`, `component="stream.health"`, `camera_id`): INFO on actual transitions only (`stream.health.transition` event with from/to/reason) — never on no-change polls (log-spam discipline; tested via capture).
- Tests (TDD, RED first; fake clock ONLY — zero real sleeps, assert suite runs fast): `tests/unit/test_stream_health.py` covering at minimum:
  1. initial state `UNKNOWN`, no transition emitted at construction;
  2. first frame → `ONLINE` + transition (`UNKNOWN→ONLINE`, reason frame-received);
  3. repeated frames stay `ONLINE` with `None` returns (no duplicates);
  4. exact boundaries: at `silence == degraded_after` → still `ONLINE`/`None`; just over → `DEGRADED` + transition; same pair for `offline_after` from `DEGRADED`;
  5. direct `UNKNOWN→DEGRADED→OFFLINE` progression with NO frames ever (pre-first-frame silence);
  6. recovery: `DEGRADED→ONLINE` and `OFFLINE→ONLINE` on frame (reason frame-received);
  7. no-duplicate polls: repeated `poll()` in same silent state → `None` every time;
  8. invalid timestamps: NaN/+inf/negative to `notify_frame` and `poll` → `ValueError`; out-of-order older frame ignored (state + `last_frame_at` unchanged);
  9. bad thresholds: `degraded_after >= offline_after`, zero/negative → `ValueError`;
  10. fake-clock determinism: scripted clock sequence produces exact transition list (assert full sequence equality);
  11. logging discipline: transitions log once each; silent polls log nothing (capture-based);
  12. thread smoke: concurrent frame-notify + poll threads complete without exception and end in a legal state (join timeouts; exact end-state asserted only where deterministic — e.g. final poll after joining).
- Contract-first: module docstring documents states, thresholds, strict-greater boundaries, no-duplicate rule, out-of-order policy, and what this machine does NOT do (reconnect/backoff = P1-005; events/persistence = later).
