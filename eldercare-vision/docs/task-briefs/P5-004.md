# Task Brief: P5-004 — Health, System & Camera APIs

- **Task ID:** P5-004
- **Phase:** Phase 5 — FastAPI + PostgreSQL Persistence
- **Role / Skill:** Addy `api-and-interface-design`
- **Owner:** IMPL + TEST
- **Status:** IN PROGRESS

## 1. Objectives & Scope

1. **FastAPI Application Core (`src/eldercare/api/app.py`, `src/eldercare/api/dependencies.py`):**
   - Application factory `create_app` with CORS middleware, request ID tracking middleware (`X-Request-ID`), and standardized error response handlers.
   - Standard error response envelope: `{"error": {"code": "...", "message": "...", "request_id": "..."}}` with zero stack-trace leakage.
2. **Health & Readiness Endpoints (`src/eldercare/api/routers/health.py`):**
   - `GET /health` (liveness check: `{"status": "ok"}`).
   - `GET /ready` (dependency readiness probe: checks DB `SELECT 1`, reports vision and optional services).
   - Mounted at both root (`/health`, `/ready`) and `/api/v1/` prefix.
3. **System Status Endpoint (`src/eldercare/api/routers/system.py`):**
   - `GET /system/status` (service versions, model name/version, config version, camera count, FPS, latency summary, GPU/CPU summary, integrations status).
   - Strict credential redaction (no passwords, tokens, or raw connection strings).
4. **Camera Management Endpoints (`src/eldercare/api/routers/cameras.py`):**
   - `GET /cameras` (list of registered cameras and health).
   - `GET /cameras/{camera_id}` (detailed camera telemetry and status, returning 404 `CAMERA_NOT_FOUND` if missing).
   - Absolute protection: RTSP URLs are strictly excluded from all camera API responses.
5. **Automated Testing:**
   - Contract and schema validation tests using FastAPI `TestClient` / `httpx` (`tests/unit/test_api_health_system.py`, `tests/unit/test_api_cameras.py`).
   - Error envelope and credential non-leakage tests (`tests/unit/test_api_errors.py`).

## 2. Invariants & Security Constraints

- **No Secret Leakage:** RTSP URLs, passwords, and tokens must never appear in responses.
- **Consistent Error Format:** All 4xx and 5xx responses must match `{"error": {"code": "...", "message": "...", "request_id": "..."}}`.
- **CPU & In-Memory Isolation:** Test suite executes with in-memory SQLite and mock services in milliseconds without network dependencies.

## 3. Acceptance Criteria

- All `/health`, `/ready`, `/system/status`, `/cameras`, and `/cameras/{camera_id}` endpoints return compliant JSON schemas matching `API_SPEC.md`.
- Unfound camera IDs return HTTP 404 with `CAMERA_NOT_FOUND` code and request ID.
- 100% test pass rate with 0 regressions.
- Ruff lint and formatting remain 100% clean.
