# P1-003 — Bounded latest-frame queue

## Purpose
Implement the bounded latest-frame queue for the RTSP pipeline: when processing falls behind, stale frames are discarded deterministically so the newest frame is always available. Freshness over completeness, never unbounded, never blocking. Also closes the four deferred P1-002 docs/precision minors (same subsystem).

## Requirements
- New module `src/eldercare/vision/stream/queue.py` (stdlib only: `threading`, `collections.deque`; type hints on all public APIs; no bare `except`):
  - `LatestFrameQueue` — payload-AGNOSTIC (stores opaque frame objects; the `Frame` observation contract is a later task — do NOT invent it here):
    - `__init__(maxsize: int = 2)`: `maxsize >= 1` else `ValueError` naming the bad value. Default 2 per `ARCHITECTURE.md` §4 (queue size 1–2); document the default's provenance.
    - `put(frame) -> bool`: non-blocking ALWAYS (never waits, never raises for full). If full, deterministically drops the OLDEST frame (`dropped += 1`), stores the newest, returns `True` if a drop occurred else `False`? — contract-first: pick the return semantic, document it in the docstring, test it. Recommended: return `True` when the frame was stored without dropping, `False`… no — simpler and honest: return whether a stale frame was dropped (`True` = drop occurred). Implementer picks one, documents, tests. Closed queue: `put` raises `RuntimeError("queue is closed")` (fail-fast, documented + tested).
    - `get() -> Any | None`: non-blocking pop of the OLDEST retained frame (FIFO among retained); `None` when empty (including after close). Never blocks, never raises for empty.
    - Thread-safety: single `threading.Lock` guarding all state; critical sections contain NO I/O, NO logging calls, NO user callbacks (bulk work outside the lock — state this invariant in a comment). Safe for one producer + one consumer (document the supported topology; more producers still correct via the same lock).
    - Counters (monotonic, for later P1-006 telemetry — no telemetry code here): `submitted: int` (accepted puts, incl. those causing a drop), `dropped: int` (discarded stale frames), `depth: int` property (current buffer size, `0 <= depth <= maxsize` invariant). `clear() -> None`: empties buffer, counters stay monotonic (documented + tested). `close() -> None`: idempotent, sets closed flag (document put/get-after-close semantics + test).
    - Retention semantics (document + test): buffer always holds the LAST `maxsize` frames in arrival order; `get()` yields oldest-retained first.
    - `__repr__`: `maxsize/depth/submitted/dropped/closed` — payload-free (frames may hold images; never repr payloads).
- P1-002 deferred minors (same file `vision/stream/capture.py`, docs/precision ONLY — read each finding in `docs/reviews/P1-002-review.md` and resolve as specified; no behavior change beyond what the reviewer explicitly frames as consistency):
  1. No-throw docstring overclaim re `BaseException`: correct the docstring to state the EXACT guarantee (`Exception` contained; `BaseException` propagates) — docs fix.
  2. Thread-safety undocumented: add a single-owner contract note to the `RtspCapture` docstring (one thread owns open/read/release; cross-thread use requires external sync; the queue — not the capture — is the thread-safe handoff). Docs fix, no locks added.
  3. `__exit__` imprecise signature: correct annotations to the conventional `(exc_type, exc_value, traceback)` types. Precision fix.
  4. Failed-open release swallow vs `release()` arming `last_error`: align to ONE documented behavior with a test (either arm consistently or document-why-silent — implementer picks, reviewer judges; minimal diff).
- Tests (TDD, RED first): `tests/unit/test_frame_queue.py` covering at minimum: empty get→None; single roundtrip; invalid maxsize (0/negative); overflow drop-oldest at maxsize 1 AND 2; newest retention after N overflows; FIFO ordering among retained; put return semantic; clear (depth 0, counters monotonic); close (idempotent, put-after-close, get-after-close drain/None); dropped-counter exactness; concurrent producer/consumer (2+ threads, thousands of puts, `join(timeout=…)` asserting no deadlock + invariant `submitted == received + dropped + depth` + `depth <= maxsize` sampled under load).
- Perf note (performance-optimization, light): the concurrency test IS the measurement — record thread counts, op counts, and wall time in the report (no optimization target; this task establishes the mechanism, P1-006/Phase 9 measure it).
