## Requirements (authoritative)
- `CONSTRAINTS.md` §11: CPU, RAM, GPU utilization, GPU VRAM measured data.
- Source-driven reality: `.venv` has NO psutil/torch and no installs allowed
  → stdlib-only collection (`os.cpu_count`, guarded `os.getloadavg`,
  guarded Linux `/proc/meminfo`, lazily-guarded `torch.cuda` mirroring the
  `api/routers/system.py` pattern). Anything unavailable is `None`
  (unknown, never zero/fabricated). Real values appear on real runs.
- Goal rules: explicit units, bounded state, no secrets, deterministic
  snapshots, injectable readers (unit tests without sleeps/hardware).

## Scope
- `mqtt/host_telemetry.py` (new): frozen `HostTelemetry` (`schema_version`,
  UTC ISO stamp, `node`, `camera_id` attachment point, optional cpu_count,
  load 1m/5m/15m, mem total/available MB, gpu device/name/VRAM MB);
  guarded reader functions (each never raises); `collect_host_telemetry()`;
  deterministic `to_dict()`/`to_json()`.
- `mqtt/publisher.py` (+ tested): `publish_metrics()` generalized to a
  `TelemetrySnapshot` protocol both snapshot types satisfy (no duplication).
- Tests: `tests/unit/test_mqtt_host_telemetry.py` — meminfo parsing,
  cpu/load injection, torch-absent/present paths, all-unknown platform,
  determinism, publish wiring.
