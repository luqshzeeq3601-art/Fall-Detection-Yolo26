# P1-001 — Camera config model

## Purpose
Define the typed camera configuration model for the RTSP stream manager: identity, enabled state, RTSP source validation, and future-safe metadata — with credentials that can never leak. Configuration and validation ONLY; no streams opened.

## Requirements
- New module `src/eldercare/vision/stream/camera.py` (stdlib + pydantic v2 only; NO `cv2` import anywhere in this task — a grep proof is required):
  - `CameraConfig(BaseModel)`, frozen (`model_config = ConfigDict(frozen=True, hide_input_in_errors=True)` — verify `hide_input_in_errors` is honored for `BaseModel` against installed pydantic 2.13.4; the acceptance test is behavioral: `str(exc)` never contains the password):
    - `camera_id: str` — `min_length=1, max_length=64`, pattern `^[A-Za-z0-9_-]+$` (stable identity, safe for topics/paths/URLs).
    - `name: str` — `min_length=1, max_length=128` (human-readable; strip surrounding whitespace via validator, reject whitespace-only).
    - `enabled: bool = True` (strict bool — no truthy-string coercion; non-bool → error).
    - `rtsp_url: str` — validated: scheme MUST be `rtsp` or `rtsps` (document why: this is the RTSP stream manager; mirror-case documenting the deliberate narrowing vs P0-005 `Settings.RTSP_URL` which accepts any scheme), hostname required, port numeric when present. Credential-bearing URLs (`rtsp://user:pass@host…`) are ACCEPTED (cameras need auth) but the raw value must never surface (see redaction rules). Empty string REJECTED here (unlike global settings: a camera entry with no source is a configuration error — document this deliberate difference).
    - Future-safe inert metadata (no behavior attached): `location: str | None = None` (max 128), `description: str | None = None` (max 512). Reserved for later phases; no runtime reads them.
  - Multi-camera future-safety WITHOUT runtime: pure function `ensure_unique_camera_ids(configs: Sequence[CameraConfig]) -> None` raising `ValueError` naming the duplicated `camera_id` (no logging of URLs inside). No registry class, no connection logic.
  - Secret safety (reuse P0-005 by import — do NOT reimplement):
    - `__repr__` and `__str__` MUST render `rtsp_url` via `redact_rtsp_url` (plus `UNPARSEABLE_URL_SENTINEL` passthrough semantics inherited).
    - `model_dump_safe() -> dict` returning `model_dump()` with `rtsp_url` replaced by its redacted form (for future API-safe serialization per API_SPEC NFR-021; no FastAPI code in this task).
    - Custom validators raise generic messages that never embed the input value (e.g. `"rtsp_url must be a valid rtsp(s) URL with host"`); combined with `hide_input_in_errors`, `str(ValidationError)` must be password-free — tested adversarially.
- Also add `src/eldercare/vision/stream/__init__.py` (docstring only, mirrors P0-002 convention) and DELETE `src/eldercare/vision/stream/.gitkeep` (redundant once real code exists).
- Tests (TDD, RED first): `tests/unit/test_camera_config.py` covering at minimum:
  1. valid minimal config (no credentials) + valid credentialed + valid disabled + valid with metadata;
  2. malformed: missing scheme, wrong scheme (`http`), missing host, non-numeric port, empty `rtsp_url`;
  3. missing required: each of `camera_id`/`name`/`rtsp_url` absent → error naming the field;
  4. identity rules: illegal `camera_id` chars, overlong id/name, whitespace-only name, non-bool `enabled`, overlong metadata;
  5. credential-bearing URL accepted AND redacted in `repr`, `str`, `model_dump_safe()`, logger JSON line (via P0-006 logger in-test), and `str(ValidationError)` from a NEARBY failing field (e.g. bad `camera_id` + credentialed URL → error text password-free);
  6. non-string/adversarial values: `None`/int/dict/list for each field, extremely long (10k) string, unicode, `rtsp://user:p@ss/w?x#y z@host/stream` shape;
  7. `ensure_unique_camera_ids`: duplicates → `ValueError` naming the id; empty/all-unique → None;
  8. `model_dump()` (raw) still holds the real URL internally (needed later by the capture layer) while `model_dump_safe()` does not — assert both sides.
- Contract-first (api-and-interface-design): the module docstring documents the field contract + the deliberate differences from P0-005 `Settings` (scheme restriction, empty-rejected, frozen model). Validate at the boundary (model only); no validation scattered elsewhere.
