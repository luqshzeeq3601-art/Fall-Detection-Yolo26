# P10-005 — Task Brief: Separate Enrichment Persistence and Events

## Objective
Implement the end-to-end `AgentEnrichmentOrchestrator` integrating asynchronous job processing, privacy containment, VLM provider execution, schema validation, database persistence in `agent_enrichments`, MQTT event publishing (`eldercare/{site_id}/{camera_id}/agent`), and WebSocket broadcasting without altering the deterministic vision detector.

## Scope
- **Agent Orchestration (`src/eldercare/agents/orchestrator.py`)**:
  - `AgentEnrichmentOrchestrator` linking `AsyncEnrichmentService`, `VLMProvider`, `EvidencePrivacyBoundary`, `IncidentService`, `MqttPublisher`, and `ConnectionManager`.
  - Step-by-step pipeline:
    1. Incident context & evidence preparation with privacy sanitization.
    2. Versioned prompt construction.
    3. Asynchronous VLM provider inference with per-call timeout/retry.
    4. Strict output schema parsing and validation.
    5. Database recording in `agent_enrichments` table via `IncidentService.record_enrichment(...)`.
    6. Real-time event broadcasting (MQTT `agent.enrichment.completed` / WebSocket `agent.enrichment`).
    7. Failure isolation: Handled failures (timeout, validation error, rate limit) record `status="failed"` / `status="timed_out"` without throwing unhandled exceptions.
- **Integration Test Suite (`tests/integration/test_agent_enrichment_flow.py`)**:
  - End-to-end async submission, execution, database persistence, MQTT publication, and WebSocket broadcast.
  - Failure scenarios: Provider timeout, provider rejection, schema violation, privacy rejection.
  - Invariance assertion: Proves core incident `fall_score`, `state`, and tracker history remain 100% untouched.

## Constraints
- Complete failure isolation: VLM or DB enrichment failures must never affect real-time inference or incident persistence.
- Zero model training, zero weight modifications, zero detector threshold modifications.
