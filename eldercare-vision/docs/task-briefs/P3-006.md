# P3-006 — ByteTrack phase review gate

## Purpose
Independent review and gate verification of the complete Phase 3 ByteTrack tracking pipeline (P3-001 through P3-005): ByteTrack configuration, `TrackObservation` domain interface, bounded per-track history, track expiry/cleanup, and multi-person/occlusion isolation. Verify against all architecture, security, and quality constraints, re-evaluate all Phase 3 ledger items, execute fresh verification suites, and determine whether Phase 3 is formally accepted to close at 100% (6/6).

## Requirements
- Verify the entire Phase 3 data path against evidence, not memory:
  `PoseFrame → ByteTrack boundary (PoseTracker) → TrackedFrame → tracked_frame_to_observations() → TrackObservation → TrackHistory (bounded deque) → expire_stale() → multi-person/occlusion isolation`
  using `src/eldercare/vision/tracking/{tracker,observation,history,__init__}.py`, all Phase 3 unit and integration test suites, and relevant Phase 2 regression suites.
- Verify Phase 3 invariants and quality gates:
  1. Track IDs originate from tracking backend (`TrackBackend.track`), not synthetic counters or default numbers.
  2. Identity is strictly keyed by `(camera_id, track_id)` per AI_SPEC §5.
  3. Identity never depends on person/list position (order swaps, rotations, and reverse order preserve backend ID association).
  4. `track_id=None` never creates persistent history (fail-safe ignore).
  5. Same numeric track ID on different cameras stays isolated (distinct dictionary keys, no cross-camera collision).
  6. Zero-person and multi-person behavior remains correct (honest backend consultation, empty tuples on zero-person, distinct histories on multi-person).
  7. Bbox, 17 keypoints, and detection/keypoint confidences remain attached to the correct person bit-for-bit with no thresholding.
  8. Per-track histories remain bounded by `max_observations` (maxlen deque) with deterministic oldest-first eviction.
  9. Timestamp monotonicity enforced: `timestamp >= last` appends; out-of-order `timestamp < last` fails closed with `ValueError` and leaves store unchanged.
  10. Stale histories expire strictly when `now - last_timestamp > max_idle_seconds` (at-boundary survives).
  11. Active histories are not removed early; expiry is idempotent; reused track IDs after expiry start fresh with zero ghost observations.
  12. Temporary occlusion follows backend-assigned identity exactly (same-ID continues, new-ID forks).
  13. No cross-person or cross-camera state leakage.
  14. No Ultralytics/ByteTrack/framework objects leak into downstream domain contracts (`TrackObservation`, `TrackHistory`).
  15. Normal CI remains CPU-safe with no hidden GPU/network/download/sleep dependency; zero sleeps in production.
- Carryovers & ledger re-evaluation:
  Re-evaluate all Phase 3 Minor and FYI items (P3-001..P3-005). Determine if any become blocking at the phase boundary.
- Fresh verification in project `.venv`:
  - P3-001 suites (`tests/unit/test_pose_tracker.py`, `tests/integration/test_tracked_pose_sequence.py`)
  - P3-002 suites (`tests/unit/test_track_observation.py`, `tests/integration/test_track_observation_sequence.py`)
  - P3-003 suites (`tests/unit/test_track_history.py`, `tests/integration/test_track_history_sequence.py`)
  - P3-004 suites (`tests/unit/test_track_expiry.py`)
  - P3-005 suites (`tests/unit/test_multi_person_isolation.py`, `tests/integration/test_occlusion_sequences.py`)
  - Phase 2 regression suites (`tests/ai_regression/test_pose_regression.py`, `tests/unit/test_pose_adapter.py`, `tests/unit/test_pose_pipeline.py`, `tests/unit/test_pose_timing.py`)
  - Full `pytest` (expect 626 passed)
  - `ruff check .` and `ruff format --check .`
