# P4-003 — Fall State Machine: Task Brief

## 1. Objective
Implement the deterministic, temporal fall state machine for ElderCare Vision according to `AI_SPEC.md` §7, `ARCHITECTURE.md`, and `ACCEPTANCE_CRITERIA.md` (AC-020..AC-025).

## 2. Requirements & State Transition Matrix
- **States**:
  - `NORMAL`: Upright standing, walking, sitting, or standard ADL.
  - `DESCENT_CANDIDATE`: Rapid downward descent or abrupt posture collapse detected in sliding window.
  - `DOWN_CONFIRMING`: Multi-frame down/horizontal posture confirmation after descent. Single horizontal frame is never sufficient.
  - `FALL_CONFIRMED`: Down posture sustained for $\ge T_{\text{confirm}}$ (e.g. 1.0s). Generates fall event.
  - `RECOVERY`: Person regains upright posture or track terminates.
- **Per-Track Isolation**:
  - State machine operates independently per `(camera_id, track_id)`.
  - Stale tracks can be evicted cleanly.
- **Timing & Transitions**:
  - Time-driven by observation timestamps (no `time.sleep`, no `time.time()` in domain logic).
  - Configurable timing parameters via `FallStateMachineConfig`.
- **Framework Freedom**:
  - Pure Python stdlib and dataclasses; zero imports of `torch`, `ultralytics`, or `cv2`.

## 3. Implementation Targets
- `src/eldercare/fall_engine/state_machine/states.py` (`FallState`, `FallStateTransition`, `FallEvent`)
- `src/eldercare/fall_engine/state_machine/config.py` (`FallStateMachineConfig`)
- `src/eldercare/fall_engine/state_machine/machine.py` (`TrackFallStateMachine`, `FallStateMachineManager`)
- `src/eldercare/fall_engine/state_machine/__init__.py`
- `src/eldercare/fall_engine/__init__.py` (re-exports)

## 4. Verification Plan
- Unit tests: Every valid transition, every invalid/forbidden transition, candidate abort, down-confirming abort/stand-up, timeout triggers, config customization.
- Integration tests: End-to-end full sequence evaluation with synthetic fixtures (walking, sitting, bending, fall-to-rest, fall-with-recovery, multi-person concurrent tracks).
- AST and linter checks.
