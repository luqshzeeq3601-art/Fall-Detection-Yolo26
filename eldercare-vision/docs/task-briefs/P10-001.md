# P10-001 — Task Brief: Asynchronous Enrichment Job & State Management

## Objective
Implement an asynchronous, non-blocking enrichment job queue and lifecycle state machine for ElderCare Vision incidents, ensuring complete decoupling and failure isolation from the real-time deterministic vision pipeline per ADR-003 and TASK_SKILL_MATRIX.md.

## Scope
- Domain state definitions:
  - `EnrichmentStatus`: `PENDING`, `IN_PROGRESS`, `COMPLETED`, `FAILED`, `TIMED_OUT`, `SKIPPED`.
  - `EnrichmentJob`: Metadata envelope tracking `job_id`, `incident_id`, `camera_id`, timestamps, attempts, status, and error details.
- Asynchronous service & worker (`AsyncEnrichmentService`):
  - Bounded in-memory job queue with configurable concurrency limit.
  - Non-blocking submission (`submit_job(...)` / `enqueue_incident(...)`).
  - Idempotency & deduplication: prevent redundant concurrent enrichment runs on the same incident.
  - Graceful lifecycle management: asynchronous start, queue drain, and clean shutdown.
  - Strict failure containment: all worker exceptions are caught, logged with redaction, and recorded without propagating to the core pipeline.
- Unit test suite:
  - `tests/unit/test_agent_async_lifecycle.py` verifying state transitions, concurrent submission safety, idempotency, failure isolation, and shutdown behavior.

## Requirements & Constraints
- The deterministic vision pipeline and incident persistence must remain 100% authoritative.
- Core detector must NEVER wait for or depend on Agent/VLM enrichment.
- Zero model training, zero weight modifications, zero threshold modifications.
- Unit tests must be hermetic and execute without external network or provider dependencies.
