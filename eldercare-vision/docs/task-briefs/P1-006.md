# P1-006 — Capture telemetry

## Purpose
Implement lightweight, thread-safe capture telemetry that AGGREGATES existing Phase 1 component state (queue, health, reconnect) plus its own bounded frame-timing record — exposing a stable typed snapshot for later consumers (Phase 7 MQTT, dashboard, UAT). No new measurement backends, no behavior change to capture.

## Requirements
- New module `src/eldercare/vision/stream/telemetry.py` (stdlib only: `threading`, `time`, `collections.deque`, `dataclasses`; type hints on all public APIs; no bare `except`):
  - `CaptureSnapshot` frozen dataclass (the stable contract — field names are the P1-006 API; document each):
    `camera_id: str`, `captured_at: float` (snapshot clock time), `capture_fps: float | None` (`None` = unknown/no data — NEVER a fabricated rate), `frames_received: int` (telemetry-owned count), `queue_submitted: int | None`, `queue_dropped: int | None`, `queue_depth: int | None` (`None` when no queue attached — unknown, not zero), `reconnect_attempts: int | None`, `reconnect_failures: int | None` (consecutive_failures; name it exactly `reconnect_failures` and document it mirrors the controller's consecutive counter), `health_state: str | None` (lowercase state value or `None` when unattached), `last_frame_at: float | None`, `seconds_since_last_frame: float | None`. Plus `to_dict() -> dict` (JSON-safe primitives only; `None`s preserved, never stringified).
  - `CaptureTelemetry`:
    - `__init__(camera_id: str, queue: LatestFrameQueue | None = None, health: StreamHealthMonitor | None = None, reconnect: ReconnectController | None = None, clock: Callable[[], float] = time.monotonic, fps_window_seconds: float = 5.0)`: validates `fps_window_seconds > 0` else `ValueError`; owns ONLY a frame-timestamp deque + `frames_received` counter. Component refs are READ-ONLY handles (never mutated, never configured — assert this discipline in tests).
    - `note_frame(timestamp: float | None = None) -> None` (`None` → `clock()`): validates like health timestamps (`ValueError` on non-finite/negative); appends to deque, prunes entries `<= now - window`, enforces a hard `MAX_FRAME_TIMESTAMPS` safety cap (constant, e.g. 16384 — document the number and why; memory bound even if the clock jumps); `frames_received += 1`. Out-of-order older timestamps: accept-and-prune (document; frames are observations, not state — unlike health, no ignore rule; justify in docstring).
    - `snapshot(now: float | None = None) -> CaptureSnapshot`: assembles WITHOUT mutating any component (read-only proof test required); FPS = (# timestamps with `ts > now - window`) / `fps_window_seconds`, with `< 2` timestamps in window → `None` (unknown, documented — a single frame is not a rate); result is a plain float (never NaN/±Inf by construction — assert in tests incl. strict `json.dumps(..., allow_nan=False)` round-trip of `to_dict()`).
    - Thread-safety: own `threading.Lock` for deque/counter; component getters called WITHOUT holding the telemetry lock across calls (acquire-copy-release per read; document the lock-ordering rule: telemetry never holds its lock while calling component code — snapshot assembles from locally-copied values). No I/O, logging, or callbacks inside any critical section.
    - `__repr__`: `camera_id/frames_received/fps/depth/health` — numeric/id/enum only, no payloads, no URLs (none exist here by construction).
- P0-006 deferred logging minors (raw `record.name`; unguarded `json.dumps`) — relevance rule: this task MUST guarantee snapshot strict-JSON-safety (tested); `logger.py` itself may be touched ONLY if the implementer proves a direct telemetry requirement AND the diff is minimal (≤5 lines, no behavior change to existing log output) — otherwise explicitly defer with written reason. Reviewer judges the call.
- Tests (TDD, RED first; fake clock ONLY, zero real sleeps): `tests/unit/test_capture_telemetry.py` covering at minimum:
  1. empty snapshot: all-`None`/zero contract exact (`fps None`, `frames_received 0`, unattached fields `None`);
  2. scripted frames → EXACT fps values (e.g. 10 frames over 5s window → `2.0`; window-boundary exclusion: frame at exactly `now - window` excluded — strict `>`; assert equality);
  3. single frame → `fps None` (no fabrication);
  4. pruning: old frames excluded from fps AND deque length shrinks;
  5. bounded memory: 100k rapid notes → `len(deque) <= MAX cap` (white-box via public behavior? — assert through `to_dict`+fps sanity + a `len()` accessor ONLY if you add a documented `frame_window_size` introspection property; do NOT expose internals otherwise);
  6. live aggregation: real queue/health/reconnect trio mutated through their own APIs → snapshot mirrors (`submitted/dropped/depth/attempts/failures/health/last_frame_at`) with exact equality;
  7. read-only proof: component counters/states identical before/after 100 snapshots;
  8. thread smoke: concurrent `note_frame` + `snapshot` threads, join timeouts, no exception, final snapshot self-consistent (`frames_received` == notes issued);
  9. credential-free: credentialed config driving the trio → snapshot dict + repr contain no password/token/URL (assert absence; host may appear ONLY if a component already exposes it — assert no userinfo);
  10. strict JSON: `json.dumps(to_dict(), allow_nan=False)` passes on empty, populated, and post-prune snapshots;
  11. invalid inputs: bad window, NaN/negative note timestamps → `ValueError`.
- Contract-first: module docstring documents the `None`-means-unknown rule, fps definition + boundary, ownership map (telemetry owns ONLY timestamps+received; everything else read live), lock-ordering rule, and what is NOT here (Prometheus/OTel/MQTT/DB/hardware/dashboard/Phase-2).
