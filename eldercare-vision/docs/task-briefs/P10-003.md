# P10-003 — Task Brief: Provider Client Timeout, Retry, and Error Normalization

## Objective
Implement a resilient, asynchronous Agent/VLM provider client (`VLMProviderClient` / `HTTPVLMProvider` / `MockVLMProvider`) featuring explicit per-request timeouts, bounded exponential backoff retries, normalized domain error taxonomies, and strict credential redaction per ADR-003 and TASK_SKILL_MATRIX.md.

## Scope
- Domain error hierarchy:
  - `ProviderClientError`: base exception.
  - `ProviderTimeoutError`: raised when requests exceed `timeout_seconds`.
  - `ProviderRateLimitError`: raised on HTTP 429 status.
  - `ProviderAuthError`: raised on HTTP 401/403 status (never retried).
  - `ProviderMalformedResponseError`: raised when payload cannot be parsed.
  - `ProviderConnectionError`: raised on DNS or transport connection loss.
- Provider implementations:
  - `VLMProvider` protocol defining `async def generate_enrichment(...)`.
  - `MockVLMProvider`: deterministic in-memory provider supporting programmable response templates, simulated latencies, and error injection for unit/soak testing.
  - `HTTPVLMProvider`: standard asynchronous vision-language API client with:
    - Strict per-call timeout enforcement.
    - Bounded retry loop (default `max_retries=2`) with exponential backoff.
    - Retry gating: retries only transient failures (429, 502, 503, 504, transport timeout); fails immediately on 400/401/403/422.
    - Injectable `sleep_func` for zero-delay unit testing.
    - Secret redaction: API keys are masked in all exception strings, logging envelopes, and repr representations.
- Test suite:
  - `tests/unit/test_agent_provider_client.py` covering timeout enforcement, retry limits, backoff calculation, auth rejection, malformed responses, and secret masking.

## Requirements & Constraints
- No infinite retry loops.
- No real sleeps in normal unit tests (inject mock sleep).
- Zero secret / API key leakage in logs or exceptions.
- Zero model training, zero weight modifications, zero threshold modifications.
