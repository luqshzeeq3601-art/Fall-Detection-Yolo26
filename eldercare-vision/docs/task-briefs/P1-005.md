# P1-005 — Reconnect/backoff

## Purpose
Implement bounded exponential reconnect/backoff around the existing `RtspCapture` and `StreamHealthMonitor`: deterministic capped delays on a fakeable clock/sleep, reset on recovery, clean cancellation, no busy-looping, minimal retry counters — with credentials never leaking.

## Requirements
- New module `src/eldercare/vision/stream/reconnect.py` (stdlib only: `threading`, `time`; type hints on all public APIs; no bare `except`):
  - `ReconnectPolicy` frozen dataclass: `base_delay: float` (default 1.0, must be `> 0`), `multiplier: float` (default 2.0, must be `>= 1.0`), `max_delay: float` (default 30.0, must be `>= base_delay`), `max_attempts: int | None` (default `None` = retry until stopped; when set must be `>= 1`). Invalid → `ValueError` naming the violated relation. Pure method `delay_for(attempt: int) -> float` (`attempt >= 1`, else `ValueError`): `min(base_delay * multiplier ** (attempt - 1), max_delay)` — deterministic, NO jitter (document why: single-camera local POC determinism beats thundering-herd avoidance here; jitter is a documented later option, not implemented).
  - `ReconnectController`:
    - `__init__(config: CameraConfig, capture: RtspCapture, health: StreamHealthMonitor, policy: ReconnectPolicy | None = None, sleep: Callable[[float], None] = time.sleep, clock: Callable[[], float] = time.monotonic)`: stores refs (does NOT own/create them — DI for tests); `sleep`/`clock` injected so tests perform zero real sleeping. Validates nothing beyond storing (components pre-validated); `attempts: int = 0`, `consecutive_failures: int = 0`, `last_delay: float | None = None`, internal `_stopped = False` under a lock.
    - `stop() -> None` (idempotent, thread-safe): sets stopped flag. `stopped: bool` property.
    - `attempt() -> bool` (ONE attempt, the unit under test): returns `False` immediately (no sleep, no capture call) if stopped; otherwise calls `capture.open()` → success: reset `attempts`/`consecutive_failures` to 0, `last_delay = None`, log success (INFO, `stream.reconnect.recovered`), return `True` (NOTE: does NOT touch health — no fake ONLINE; health recovers on real frames via `notify_frame`; document this honesty rule); failure: `attempts += 1`, `consecutive_failures += 1`, compute `delay_for(attempts)`, `last_delay = delay`, log attempt outcome (WARNING `stream.reconnect.attempt` with attempt/delay — camera_id + numbers only, never URLs), `sleep(delay)`, return `False`. Capture exceptions are already contained by `RtspCapture` (returns False + sanitized `last_error`) — the controller must additionally sanitize anything it formats itself.
    - `connect_with_retry(max_attempts_override: int | None = None) -> bool`: loops `attempt()` until success, stopped, or effective attempt cap reached (`max_attempts_override` ?? `policy.max_attempts`); returns `True` on success else `False`. No busy-looping possible: every failing iteration sleeps `>= base_delay > 0` (document + test that sleep was called with the exact sequence).
    - Logging (P0-006 reuse, bound `service="vision"`, `component="stream.reconnect"`, `camera_id`): `attempt` (WARNING, fields attempt/max/delay), `recovered` (INFO), `gave_up` (WARNING, cap reached), `stopped` (INFO). All fields numeric/ids only.
    - `__repr__`: `camera_id/attempts/consecutive_failures/stopped` — no URLs (holds only `CameraConfig`, never formats its URL).
- Tests (TDD, RED first; fake sleep recording calls + fake clock; ZERO real sleeps — assert via suite timing): `tests/unit/test_reconnect.py` covering at minimum:
  1. policy sequence exact: `delay_for(1..N)` == `[1, 2, 4, 8, 16, 30, 30, …]` for defaults (assert list equality incl. cap flattening);
  2. custom policy values + invalid policies (base≤0, multiplier<1, max<base, max_attempts<1, attempt<1) → `ValueError`;
  3. `attempt()` success first-try: `True`, counters zeroed, no sleep called;
  4. repeated failures: `connect_with_retry(max_attempts=3)` → `False`, sleep called with EXACT `[1.0, 2.0, 4.0]`, `attempts == 3`, `consecutive_failures == 3`, `last_delay == 4.0`;
  5. recovery/reset: fail,fail,success → `True`, counters reset to 0, `last_delay is None`, 4th-attempt delay would restart at base (prove by failing again → sleep called with base);
  6. factory-raises-every-time → handled `False` path (no throw), sanitized `last_error`, sleep sequence exact;
  7. cancellation: pre-stopped `attempt()` → `False` with zero capture calls + zero sleeps; `stop()` mid-sequence (fake sleep that stops the controller) → loop exits promptly with `False`; `stop()` idempotent;
  8. recovery-no-dup-noise (integration with REAL `StreamHealthMonitor` + fake clock): drive health to OFFLINE via polls, reconnect succeeding (fake capture opens) → health STILL offline with NO transition emitted (no fake ONLINE); then `notify_frame` → exactly one `OFFLINE→ONLINE`; assert full transition list equality;
  9. credential safety: credentialed config + failing factory embedding URL/token in exceptions → `last_error`, captured log JSON lines, and `repr(controller)` all password-free;
  10. no-busy-loop: failing `connect_with_retry` with fake sleep asserts every sleep arg `>= base_delay` and sleep call count == failure count.
- Contract-first: module docstring documents the delay formula, honesty rule (open-success ≠ health-ONLINE), stop semantics, and what is NOT here (MQTT events = Phase 7; persistence = Phase 5; FPS telemetry = P1-006; backoff tuning = benchmark-driven later).
