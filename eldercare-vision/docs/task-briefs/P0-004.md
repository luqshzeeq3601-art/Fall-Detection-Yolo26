- For `postgres`/`mosquitto`: pinned upstream images (`postgres:16`, `eclipse-mosquitto:2`) — no build.
- Secrets: every credential via environment variables with REQUIRED syntax (`${POSTGRES_USER:?…}`, `${POSTGRES_PASSWORD:?…}`, `${POSTGRES_DB:?…}`). Validation runs with ephemeral inline env (e.g. `$env:POSTGRES_PASSWORD="dummy-for-config-check-only"`), recorded in the report, never written to disk.
- Networks: one explicit user-defined network (e.g. `eldercare`), all services attached; no `network_mode: host`.
- Volumes: named volumes for `postgres` data (`pgdata`) and mosquitto config/data/log (`mosquitto-conf`, `mosquitto-data`, `mosquitto-log` mounts under `deployment/mosquitto/` + named data volume — keep it simple: two named volumes `pgdata`, `mosquitto-data` plus a read-only bind for broker config skeleton created in `deployment/mosquitto/` ONLY if needed for validation; prefer named volumes + document the future broker-conf path in comments).

- GPU: `deploy.resources.reservations.devices` (`driver: nvidia`, `count: 1`, `capabilities: [gpu]`) on `vision` ONLY. No GPU blocks elsewhere.
- `restart: unless-stopped` on long-running services; `depends_on` with `condition: service_healthy` where a healthcheck exists (postgres at minimum: `pg_isready`); healthchecks only where the image supports them without custom scripts.
- Remove the obsolete top-level `version:` key (compose v5 warns on it — verify `config` output is warning-free or record the warning).
- Environment fact (verified by coordinator 2026-09-20): Docker client 29.6.1 + compose v5.2.0 present, **daemon DOWN** (`docker version` server call fails). Therefore: `docker compose config` (client-side, no daemon needed) is REQUIRED and must pass; `pull`/`up`/`ps` are environment-blocked — record as such, do not fake them.
