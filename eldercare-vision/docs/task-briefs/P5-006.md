# Task Brief: P5-006 — Append-Only Incident Review API

- **Task ID:** P5-006
- **Phase:** Phase 5 — FastAPI + PostgreSQL Persistence
- **Role / Skill:** Superpowers `test-driven-development`
- **Owner:** IMPL + TEST
- **Status:** IN PROGRESS

## 1. Objectives & Scope

1. **Human Review Submission Endpoint (`POST /incidents/{incident_id}/reviews`):**
   - Implemented on `incidents.router` in `src/eldercare/api/routers/incidents.py`.
   - Accepts `IncidentReviewCreate` request body: `label` (enum: `confirmed_fall`, `non_fall`, `uncertain`), optional `notes` (max length 2000), optional `reviewer` (max length 128).
   - Returns `IncidentReviewRead` with HTTP 201 Created status.
2. **Strict Detector Immutability:**
   - Every submitted review appends a new record to the `incident_reviews` table.
   - Core detector outputs (`fall_score`, `model_name`, `model_version`, `config_version`, `evidence_features`, etc.) in `incidents` table remain completely untouched.
3. **Error Handling & Validation:**
   - Submitting a review for a non-existent `incident_id` returns HTTP 404 with structured error envelope `INCIDENT_NOT_FOUND`.
   - Submitting an invalid `label` returns HTTP 422 `INVALID_REVIEW_LABEL` / `VALIDATION_ERROR`.
   - Excessively long notes or malicious payload structure are rejected by Pydantic validation.
4. **Comprehensive Automated Testing:**
   - Unit and contract tests in `tests/unit/test_api_reviews.py` verifying successful appending, multi-review audit history, validation errors, 404 handling, and detector immutability assertions.

## 2. Invariants & Security Constraints

- **Audit Ledger (Append-Only):** Reviews can only be appended; existing review records cannot be updated or deleted through this endpoint.
- **Detector Independence:** Human reviews never overwrite or modify algorithmic fall detection scores.
- **Consistent Error Structure:** Error responses conform to `{"error": {"code": "...", "message": "...", "request_id": "..."}}`.

## 3. Acceptance Criteria

- `POST /incidents/{incident_id}/reviews` returns 201 with saved review data.
- Multiple reviews create a chronological audit chain.
- Invalid inputs and missing incidents return standard error envelopes.
- 100% test suite pass rate with 0 regressions.
- Ruff lint and formatting remain clean.
