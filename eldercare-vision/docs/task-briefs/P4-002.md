# P4-002 — Temporal feature extraction

## Purpose
Implement pure, deterministic geometry and motion temporal feature extraction over timestamped `TrackObservation` histories per `AI_SPEC.md` §6 and `ARCHITECTURE.md` §5. Provide confidence-aware features for downstream fall-state machine and confidence scoring in Phase 4.

## Requirements
- Module location: `src/eldercare/fall_engine/features/` with exports in `src/eldercare/fall_engine/features/__init__.py` and `src/eldercare/fall_engine/__init__.py`.
- Features to compute:
  1. **Single-Frame Geometry (`PoseGeometryFeatures`):**
     - Bbox height, width, and aspect ratio (`height / width`).
     - Shoulder midpoint (`left_shoulder`, `right_shoulder`).
     - Hip midpoint (`left_hip`, `right_hip`).
     - Torso vector (`shoulder_midpoint - hip_midpoint`) and torso orientation angle with respect to horizontal (90° = vertical upright, 0° = horizontal flat).
     - Body center (hip midpoint fallback to bbox center).
     - Keypoint confidence summary (mean confidence, count of present keypoints).
  2. **Temporal Motion Features over History (`TemporalFeatures`):**
     - Timestamped analysis over a configurable time window (default 1.5s).
     - Vertical displacement (pixels and normalized by person height).
     - Vertical velocity (downward rate of displacement in pixels/s and normalized heights/s).
     - Bbox height change ratio (`delta_h / initial_h`) and aspect ratio delta.
     - Torso angle change (`delta_angle`).
     - Duration of low/horizontal posture in recent window.
     - Post-descent motion stability (motion variance in recent low posture; low = motionless on floor).
     - Average keypoint confidence across history.
  3. **Robustness & Edge-Case Handling:**
     - Missing keypoints handled explicitly with graceful fallbacks (e.g. single shoulder if one is occluded, bbox center if hips occluded).
     - Zero division protection for zero-width/height bboxes or zero dt.
     - Out-of-order timestamp detection / fail-closed validation.
     - Deterministic and pure: identical inputs yield identical outputs.
     - Zero framework dependencies (no torch, ultralytics, cv2).
