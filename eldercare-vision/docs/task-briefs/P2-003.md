# P2-003 — Normalize 17-keypoint result contract

## Purpose
Implement the framework-independent pose-result adapter: convert Ultralytics YOLO26s-Pose `Results` into a stable typed internal contract (pixel boxes + confidence + 17 keypoints with explicit missingness) for downstream tracking/temporal analysis. No tracking, no thresholds, no inference here.

## Requirements
- New module `src/eldercare/vision/pose/adapter.py` (stdlib + numpy ONLY — numpy is already declared; do NOT import torch/ultralytics/cv2 at runtime so CI stays CPU-only and downstream stays framework-free):
  - `KEYPOINT_NAMES: tuple[str, ...]` — the 17 COCO-ordered names from `AI_SPEC.md` §4 (nose, left_eye, right_eye, left_ear, right_ear, left_shoulder, right_shoulder, left_elbow, right_elbow, left_wrist, right_wrist, left_hip, right_hip, left_knee, right_knee, left_ankle, right_ankle). `KEYPOINT_COUNT = 17`.
  - `Keypoint` frozen dataclass: `x: float | None`, `y: float | None`, `confidence: float`, `present: bool` with invariant `present ⟺ (x is not None and y is not None)` (enforced in `__post_init__`, violation → `ValueError`). Confidence is ALWAYS preserved (even when `present` is False — a low/invalid coord still carries a real confidence measurement).
  - `PersonPose` frozen dataclass: `bbox_xyxy: tuple[float, float, float, float]` (pixel space, `x1 <= x2 and y1 <= y2` validated), `detection_confidence: float` (finite, 0..1 validated), `keypoints: tuple[Keypoint, ...]` (exactly 17, index-aligned with `KEYPOINT_NAMES`).
  - `PoseFrame` frozen dataclass: `image_width: int`, `image_height: int` (both `> 0`), `persons: tuple[PersonPose, ...]` (empty tuple = no detections — the zero-person contract).
  - `adapt_pose_results(results) -> PoseFrame`: duck-typed input (reads ONLY `results.keypoints` [`.xy` (N,17,2), `.conf` (N,17)] and `results.boxes` [`.xyxy` (N,4), `.conf` (N,)] plus image size from `results.orig_shape` (h, w)). No ultralytics import (also gate with `sys.modules` assertion in tests — adapter must work with plain stub objects). Conversion via duck-typed float extraction (works for torch tensors, numpy arrays, nested lists — verify all three in tests WITHOUT importing torch: build stubs from numpy/lists only).
  - Missingness rule (documented): a keypoint is missing ⇔ its source x or y is non-finite (NaN/±Inf) ⇔ stored as `(None, None, conf, present=False)`; finite coords stored as floats. NEVER fabricate: no zeros-for-missing, no interpolation, no thresholding (confidence policy belongs downstream — state this explicitly).
  - `keypoints is None` (Ultralytics no-detection shape) → `persons=()` (image dims still required — from `orig_shape`; if `orig_shape` itself missing/malformed → `ValueError`).
  - Fail-closed validation (`ValueError` naming the defect): keypoint dim ≠ 17; xy/conf length mismatch; boxes/person count mismatch; non-finite or out-of-range detection confidence; invalid bbox ordering; non-positive image dims; `results=None`.
  - Pixel-space decision (contract-first, documented): the contract stores PIXEL coordinates + image dims; normalization for distance-invariance is downstream's job (AI_SPEC §6). Do NOT store `xyn` (single source of truth, no dual-representation drift).
- Also add `src/eldercare/vision/pose/__init__.py` (docstring only, P0-002 convention) and DELETE `src/eldercare/vision/pose/.gitkeep`.
- Tests (TDD, RED first; CPU-only numpy/list stubs — NEVER import ultralytics/torch/cv2 in tests; assert `sys.modules` contains none of them after adapter calls): `tests/unit/test_pose_adapter.py` covering at minimum:
  1. zero-person (`keypoints=None`) → empty persons, dims kept;
  2. one-person exact values incl. conf preserved bit-for-bit (numpy + list-stub variants);
  3. multi-person (3) ordering + per-person conf;
  4. missing keypoints (NaN x, +Inf y, mixed) → `present=False`, coords None, conf preserved;
  5. malformed: 16/18 kpts, xy/conf length mismatch, boxes/person mismatch, NaN conf, bad bbox order, bad dims, `results=None` → `ValueError` each;
  6. invariant: hand-constructed `Keypoint` violating present⟺coords → `ValueError`;
  7. framework-freedom: adapter called with pure-list stubs (no numpy even) works; `sys.modules` free of ultralytics/torch/cv2 post-call;
  8. `KEYPOINT_NAMES` length 17 + spot-check first/last names.
- Contract-first: module docstring documents the representation contract (pixel + dims, missingness rule, no-threshold policy, duck-typed input surface with attribute table) and the P2-004 handoff (live Results → this function).
