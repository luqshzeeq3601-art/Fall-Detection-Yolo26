# P3-003 — Bounded per-track history

## Purpose
Implement a deterministic, bounded history store keyed by tracked-person identity for downstream temporal fall analysis. Appends `TrackObservation` objects in temporal order with oldest-first eviction; expiry/cleanup policy (P3-004) and all temporal/fall computation stay out.

## Requirements
- New module `src/eldercare/vision/tracking/history.py` (stdlib ONLY at import time — not even numpy needed; NO ultralytics/torch/cv2 import, not even lazily; reuse `TrackObservation` by import):
  - `TrackHistoryConfig` frozen dataclass: `max_observations: int` (per-track fixed maximum; validated positive int, bools rejected; default value chosen with a DOCUMENTED rationale referencing AI_SPEC §9 `history_seconds` tracking example — e.g. capacity covering ~2 s at typical frame rates — recorded as an engineering default, not a calibrated threshold).
  - `TrackHistory` class: internal `dict[tuple[str, int], deque[TrackObservation]]` with per-key `maxlen` bound (true boundedness — memory cannot grow with stream length; no unbounded structures anywhere, including key sets).
  - Key rule: history key is exactly `(camera_id, track_id)` per AI_SPEC §5. `track_id=None` observations are IGNORED (no persistent history for unassigned tracks — the architecture requires history keyed by track identity, and unassigned detections are routine, so raising would be hostile; ignoring is explicit, documented in the docstring, and tested — never silent).
  - Append rule `append(obs: TrackObservation) -> None`: validates type (fail-closed `TypeError`); per-key temporal ordering enforced on `timestamp`: first observation for a key always accepted; `timestamp >= last` accepted AND APPENDED (duplicate timestamps accepted — same-frame re-observation is legitimate, and order of arrival is preserved); `timestamp < last` → fail-closed `ValueError` naming the key and both stamps (historical evidence is never silently reordered or inserted mid-stream). Cross-key timestamps are independent (compared per-key only).
  - Eviction: when a key's deque is full, oldest-first eviction is automatic (`maxlen` semantics); newest observations always retained. Document that eviction is count-based only — time-based expiry is P3-004.
  - Read-only access: `snapshot(camera_id, track_id) -> tuple[TrackObservation, ...]` (oldest→newest; unknown key → `()` — not an error); `keys() -> tuple[tuple[str, int], ...]`; `__len__` = number of tracked keys (document). Snapshots are fresh tuples of immutable observations — callers cannot mutate internal buffers (no deque/list/reference leaks; test this).
  - Lifecycle: `remove(camera_id, track_id) -> bool` (`True` iff a history existed; unknown key → `False`, not an error); `clear() -> None` drops everything; both deterministic. `__repr__` scalar-only (counts/keys, no confidences dump).
  - Concurrency: NO locks/threads (the pose pipeline is single-owner per `pipeline.py` threading note; the queue remains the thread-safe handoff). Document single-owner assumption explicitly — do not add concurrency complexity.
  - Contract-first docstring: key rule, append/ordering/eviction rules, `None` policy, bound semantics, snapshot guarantees, lifecycle, single-owner note, what is NOT here (expiry, temporal features, velocity/angles/smoothing/scores/FSM/alerts).
- Tests (TDD, RED first; CPU-only, deterministic; NEVER import `ultralytics`/`torch`/`cv2` in tests; zero sleeps; `sys.modules` + AST framework-freedom proofs):
  - `tests/unit/test_track_history.py` (new; unique basename): config defaults/validation (incl. bool/zero/negative rejection); first observation; sequential append order; exact max-length boundary (N fills, N+1 evicts oldest, newest retained — assert full tuple equality, not just lengths); multi-append eviction sequence; separate tracks independence; separate cameras independence; `track_id=None` ignored (no key created, other keys untouched); duplicate timestamps appended in arrival order; out-of-order → `ValueError` (and store unchanged afterwards); wrong-type append → `TypeError`; unknown-key snapshot → `()`; `remove` true/false + post-remove snapshot empty + other keys intact; `clear` empties all; snapshot immutability (mutating attempts fail; internal state unchanged after caller fiddles with returned tuple — tuples are immutable, assert store intact); determinism (two identical sequences → equal snapshots); key validation on snapshot/remove (bad types fail closed); framework-freedom.
  - Small integration `tests/integration/test_track_history_sequence.py` (new): multi-frame `TrackedFrame` → `PoseTracker` (scripted backend) → `tracked_frame_to_observations` → `TrackHistory.append` over 3+ frames × 2 persons → per-track snapshots show identity-continuous, order-correct, bounded histories consumable WITHOUT tracker/framework knowledge (consumer reads `TrackObservation` fields only).
  - Cap ≤ 30 new tests total. Do NOT re-assert converter/schema/backend internals already pinned — test the NEW store contract + wiring only; state non-duplication in the report.
- Downstream-consumability: the integration test's consumer block groups/reads histories using ONLY store + `TrackObservation` APIs (proves temporal code needs no tracker knowledge; no history-policy logic beyond the store itself).
