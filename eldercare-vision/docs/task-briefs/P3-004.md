# P3-004 — Track expiry/cleanup

## Purpose
Add deterministic expiry/cleanup for stale `(camera_id, track_id)` histories on the existing P3-003 `TrackHistory` store (class `TrackHistory` in `vision/tracking/history.py` — "TrackHistoryStore" in the task order means this class), so unbounded distinct-track key growth is reclaimed. All temporal/fall computation stays out.

## Requirements
- Modify `src/eldercare/vision/tracking/history.py` (ADDITIVE ONLY — no behavior change to `append`/`snapshot`/`keys`/`remove`/`clear`; stdlib only; no new imports beyond stdlib):
  - New method `expire_stale(now: float, *, max_idle_seconds: float) -> tuple[tuple[str, int], ...]` on `TrackHistory`:
    - Activity basis: each key's LATEST accepted `TrackObservation.timestamp`.
    - Exact boundary: a key expires iff `now - last_timestamp > max_idle_seconds` (STRICTLY greater — at exactly the boundary the key SURVIVES). Document and test before/at/after.
    - `now` is caller-provided (no clocks inside — deterministic, CPU-safe, no sleeps); production callers pass capture-clock time (document).
    - Returns the expired keys as a FRESH tuple in key-insertion (dict) order (documented deterministic order); exposes no mutable internals.
    - Idempotent: repeated calls with equal arguments expire nothing further (second call returns `()` unless new appends arrived).
    - Reuse: after expiry the key is fully dropped; a later `append` for the same key starts a FRESH history (no ghost observations).
    - Fail-closed validation (naming errors): non-numeric/bool/NaN/±Inf/negative `now` or `max_idle_seconds` → `TypeError`/`ValueError`; the store is unchanged on validation failure.
    - Bulk-safe: reclaim path collects keys before deleting (no mutate-during-iteration); reclaim of thousands of stale keys tested.
  - No config change (`TrackHistoryConfig` untouched — the idle threshold is an explicit per-call policy input, not stored tuning); no locks/threads (single-owner precedent holds).
  - Docstring updates: expiry rule + boundary + `now` semantics + return-order + idempotency + reuse + P3-003-rule pointers; what is NOT here (temporal features, reactivation heuristics, time-based sampling).
- Tests (TDD, RED first; CPU-only, deterministic; NEVER import `ultralytics`/`torch`/`cv2` in tests; zero sleeps; `sys.modules` + AST framework-freedom proofs):
  - `tests/unit/test_track_expiry.py` (new; unique basename): active track survives; stale track expires (exact key returned); boundary trio (idle `<` max → survive, `==` max → survive, `>` max → expire); mixed freshness (only stale keys returned, exact tuple); multiple cameras/tracks independent; empty store → `()`; repeated cleanup idempotent (`()` second time); remove→recreate then expire (fresh history ages from new appends only); invalid time inputs fail closed (`None`/`bool`/`NaN`/`Inf`/`-1`/strings for `now` and `max_idle_seconds`, store unchanged); surviving-history integrity (post-expiry snapshots of survivors bit-exact, ordering intact); bulk reclamation (e.g. ≥1000 stale keys → all returned, store empty, other structures intact, completes fast); return-type/freshness (tuple, not list/deque; mutating it cannot affect the store); unknown-key-free operation (no key created by expiry itself); framework-freedom.
  - Cap ≤ 30 new tests. Do NOT re-assert append/ordering/eviction/snapshot/converter internals already pinned — test the NEW expiry contract only; state non-duplication in the report.
- `src/eldercare/vision/tracking/__init__.py`: NO CHANGE expected (no new top-level names — expiry is a method). If the implementer finds an export genuinely required, additive-only with reviewer justification; otherwise leave byte-identical.
