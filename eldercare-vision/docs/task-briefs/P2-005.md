# P2-005 — Add inference timing metrics

## Purpose
Add lightweight, deterministic inference timing instrumentation around the existing P2-004 pose pipeline without changing its functional behavior. Record the Phase 2 processing timings supported by the current architecture — model prediction time vs pose-result adaptation time plus overall pipeline processing duration — through a stable typed contract suitable for later telemetry/API use. Timing uses a monotonic high-resolution clock through an injectable boundary so CPU CI tests are deterministic with zero sleeps.

## Requirements
- New module `src/eldercare/vision/pose/timing.py` (stdlib ONLY — no numpy/ultralytics/torch/cv2; grep-proof):
  - `PoseTiming` frozen dataclass: `predict_ms: float`, `adapt_ms: float`, `total_ms: float`. All values are MILLISECONDS (explicit unit — never seconds), each validated in `__post_init__` as finite and `>= 0` (violation → `ValueError` naming the field; bools rejected). `to_dict() -> dict[str, float]` returning JSON-safe primitives (must pass `json.dumps(..., allow_nan=False)` — asserted in tests).
  - `timings_from_stamps(t0: float, t1: float, t2: float) -> PoseTiming` pure helper: `predict_ms = (t1 - t0) * 1000.0`, `adapt_ms = (t2 - t1) * 1000.0`, `total_ms = (t2 - t0) * 1000.0`. Fail closed with naming `ValueError` on non-finite stamps or backwards stamps (`t1 < t0` or `t2 < t1` — a clock anomaly is never hidden as a negative or clamped duration). Bool inputs rejected. Document the stamp ordering contract (`t0` = pre-predict, `t1` = post-predict/pre-adapt, `t2` = post-adapt).
  - Module docstring documents: units (ms), what is measured (predict + adapt + total ONLY — RTSP capture latency and queue waiting time are explicitly NOT inference metrics and are never included), the `None`-means-unmeasured rule (see pipeline result field), and the later-telemetry handoff (CONSTRAINTS §11 `inference latency` is satisfied by `total_ms`; per-stage breakdown by `predict_ms`/`adapt_ms`).
- Modify `src/eldercare/vision/pose/pipeline.py` (ADDITIVE ONLY — no functional behavior change):
  - Import `PoseTiming`/`timings_from_stamps` from `timing.py` (same subpackage; no new third-party deps).
  - `PosePipeline.__init__` gains optional `timer: Callable[[], float] = time.perf_counter` (validate callable, else `TypeError`). Document the two-boundary rule: `clock` (default `time.monotonic`) stamps OBSERVATIONS (`capture_timestamp` fallback); `timer` (default `time.perf_counter`) measures DURATIONS. They are separate injectable boundaries so tests control each independently; neither is ever used for the other's purpose.
  - `PosePipelineResult` gains field `timing: PoseTiming | None = None` (default `None` preserves backward compatibility — the existing test at `tests/unit/test_pose_pipeline.py:199` constructs the result without timing and must keep passing unmodified). `__post_init__` validates `None` or a `PoseTiming` instance (else `TypeError`). Document: `None` = not measured (hand-constructed results only); every pipeline-produced success result carries a real `PoseTiming`.
  - `process_frame`: `t0 = self._timer()` → `results = predictor.predict(...)` → `t1 = self._timer()` → `adapt_pose_results(results)` (inside the existing try; adapter `ValueError`s keep their frame-context wrapping) → `t2 = self._timer()` → `timing = timings_from_stamps(t0, t1, t2)` → attach to the result. Timer anomalies propagate as naming `ValueError` (never a fabricated or negative duration). Predictor exceptions propagate unwrapped exactly as today (no timing fabricated). The existing `orig_shape`/image cross-check, `del results` no-retention rule, identity propagation, and error semantics are byte-for-byte unchanged.
  - `process_capture_read` / `process_queued_frame`: unchanged delegation (timing flows automatically via `process_frame`); `None` paths still return `None` with no timing object created (do not fabricate timings when a stage did not execute).
  - Log record UNCHANGED: the existing `pose.frame_processed` DEBUG record keeps its exact event/keys (`frame_id`, `person_count`; `test_process_frame_logs_one_structured_record` filters on them and must keep passing). Timings are exposed via the result contract only, not logs.
  - `__repr__` unchanged (`camera_id` only).
- Tests (TDD, RED first; CPU-only fakes + programmed fake timers — NEVER import `ultralytics`/`torch`/`cv2` in tests; zero real sleeps; assert `sys.modules` introduces none of them):
  - `tests/unit/test_pose_timing.py` (new; basename is unique — no import collision): `PoseTiming` validation (negative/NaN/Inf/bool per field → `ValueError`; `to_dict` strict-JSON round-trip); `timings_from_stamps` exact math (`t = [100.0, 100.010, 100.025]` → `10.0 / 15.0 / 25.0` ms exact); zero-duration (`t0 == t1 == t2` → `0.0/0.0/0.0`, allowed); multi-stage separation (distinct predict vs adapt values); backwards stamps (`t1 < t0`, `t2 < t1` → `ValueError` each); non-finite stamps (NaN/Inf → `ValueError`); pipeline integration with a programmed `FakeTimer` sequence (zero-person → `persons == ()` + timing exact; one-person exact pose values bit-for-bit + timing exact; three-person ordering/conf + timing exact); missing-keypoint passthrough keeps timing; repeated calls produce fresh per-call timings from the advancing timer (no accumulation, no stored state growth — `vars(pipeline)` gains only `_timer` vs P2-004); failure paths (predictor raises → propagates, no result; adapter malforms → `ValueError`, no result; `process_capture_read(False/None)` and empty queue → `None` with no timer consumption beyond the contract); clock/timer independence (advance `clock` without moving `timer` → `capture_timestamp` changes, timing unchanged; and vice versa); contract regression (same fake `Results` through default-timer vs fake-timer pipelines → identical `pose`/`camera_id`/`frame_id`/`capture_timestamp` fields); non-callable `timer` → `TypeError`; framework-freedom (`sys.modules` + pure-list stubs); units (assert `predict_ms == 10.0` for a 10 ms gap — i.e. milliseconds, not `0.01`).
  - Regression: ALL existing files `tests/unit/test_pose_pipeline.py` (50 tests) and `tests/integration/test_pose_pipeline.py` (3 tests) must pass UNMODIFIED (proves timing did not change the 17-keypoint contract or the fake-capture e2e).
