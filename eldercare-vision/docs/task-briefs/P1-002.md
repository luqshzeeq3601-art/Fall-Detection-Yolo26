# P1-002 — RTSP capture abstraction

## Purpose
Build a small, testable RTSP capture abstraction over the validated P1-001 `CameraConfig`: explicit open/read/release lifecycle, deterministic failure handling, idempotent cleanup, and DI/mocking for tests. No reconnect, no queues, no health logic.

## Requirements
- Source-driven first (record in report): `python -c "import cv2; print(cv2.__version__)"` + which distribution provides it (`pip show opencv-python opencv-python-headless`), and the `cv2.VideoCapture` lifecycle API verified live against the INSTALLED build (`isOpened`/`read`/`release` existence + callability + `read()` return shape). Cite outputs; do not rely on remembered OpenCV API.
- New module `src/eldercare/vision/stream/capture.py` (type hints on all public APIs; no bare `except`):
  - `RtspCapture` class constructed from a `CameraConfig` plus an injectable `capture_factory: Callable[[str], VideoCaptureLike] | None = None` (default factory = `cv2.VideoCapture`; a minimal `VideoCaptureLike` `Protocol` declaring `isOpened() -> bool`, `read() -> tuple[bool, Any]`, `release() -> None` so fakes need no cv2).
  - Lifecycle: `open() -> bool` (builds capture via factory, returns `isOpened()`; factory exceptions → caught, sanitized, `False` — never raises for open-failure); `read() -> tuple[bool, ndarray | None]` (returns `(False, None)` when closed or on read failure/exception — never raises for read-failure); `release() -> None` (idempotent: safe ×N, safe when never opened, safe after failed open; releases and drops the handle); `is_opened: bool` property; context-manager (`__enter__` opens, `__exit__` releases; enter-failure behavior documented + tested).
  - Failure state: `last_error: str | None` — sanitized via P0-005 `sanitize_exception_message` (no URL creds, no tokens); cleared on successful open/read.
  - Logging (minimal, P0-006 reuse only — no telemetry): bound logger (`service="vision"`, `component="stream.capture"`, `camera_id`) emitting `capture.opened` / `capture.open_failed` / `capture.read_failed` / `capture.released` events at INFO/WARNING/DEBUG as appropriate; every emitted line must be credential-free (tested via capture).
  - `__repr__`/`__str__`: `camera_id` + opened state ONLY — never the URL in any form (safer than redacted: absent). Document this deliberate choice vs P1-001's redacted repr.
- Dependencies: declare EXACTLY what the new module top-level-imports. `cv2` + (only if directly imported) `numpy`: add ONE opencv distribution to `[project] dependencies` — prefer `opencv-python-headless>=4` (no GUI libs; deployment-appropriate) unless local verification proves otherwise; record the choice + local `import cv2` version proof. If `numpy` is imported for annotations at runtime, declare `numpy>=1` too (opencv pulls it transitively, but direct imports get explicit declarations). Re-verify `pip install -e .` after the change.
- Tests (TDD, RED first; fakes, never real streams): `tests/unit/test_capture.py` covering at minimum:
  1. open success (fake `isOpened()=True`) → `True`, `is_opened`, `last_error is None`;
  2. open failure (`isOpened()=False`) → `False`, sanitized `last_error`, no throw;
  3. factory raises (e.g. `RuntimeError("boom …credentialed-url…")`) → `False`, password absent from `last_error`;
  4. read success → `(True, frame)` passthrough of the fake frame object;
  5. read failure (`(False, None)`) and read-raises → `(False, None)`, sanitized `last_error`, no throw; read-when-closed → `(False, None)`;
  6. release idempotent (×3 + release-without-open + release-after-failed-open → no throw, handle dropped);
  7. context manager: happy path releases on exit; open-failure inside `with` behaves as documented;
  8. credential safety end-to-end: credentialed config through open/read/exception/log paths → raw password absent from `repr`/`str`/`last_error`/captured log JSON;
  9. default factory wires `cv2.VideoCapture` (assert the default is cv2-backed; behavior validated EITHER by opening a nonexistent local file expecting graceful `False` — no network — OR by mocking `cv2.VideoCapture` itself; implementer picks one and justifies; no network streams in tests ever).
- Contract-first: module docstring documents the lifecycle contract, failure semantics (return-False-never-raise for open/read; which paths CAN raise: constructor type errors, programming errors), and the deliberate differences from raw cv2 (sanitized errors, no URL in repr, DI seam).
