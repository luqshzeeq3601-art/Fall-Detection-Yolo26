# Task Brief: P5-005 — Incident List, Detail & Evidence Streaming APIs

- **Task ID:** P5-005
- **Phase:** Phase 5 — FastAPI + PostgreSQL Persistence
- **Role / Skill:** Addy `api-and-interface-design`, `security-and-hardening`
- **Owner:** IMPL + TEST
- **Status:** IN PROGRESS

## 1. Objectives & Scope

1. **Incident Query & List Endpoint (`GET /incidents`):**
   - Implemented in `src/eldercare/api/routers/incidents.py`.
   - Query filters: `camera_id` (string), `status` (string matching detector state), `review_label` (human review label filter), `from`/`from_time` (ISO datetime), `to`/`to_time` (ISO datetime), `limit` (integer 1-500, default 50), `offset` (integer >= 0, default 0), `cursor` (optional).
   - Returns paginated response envelope `PaginatedIncidents`: `{"items": [...], "total": int, "limit": int, "offset": int}`.
   - Preserves detector output immutability in read representations.

2. **Incident Detail Endpoint (`GET /incidents/{incident_id}`):**
   - Returns complete incident details (`IncidentDetailRead`), eagerly loading associated `evidence`, `reviews`, and `enrichments`.
   - Returns HTTP 404 with structured error envelope `INCIDENT_NOT_FOUND` if the incident ID does not exist.

3. **Evidence Streaming Endpoint (`GET /incidents/{incident_id}/evidence/{evidence_id}`):**
   - Validates existence of the incident and evidence record in the database.
   - Enforces storage sandboxing via `EvidenceStorage.resolve_safe_path()` to eliminate path traversal vulnerabilities.
   - Streams media bytes with correct media type (`image/jpeg`, `video/mp4`, `application/json`, `application/octet-stream`) and returns `X-Evidence-SHA256` checksum header.
   - Returns HTTP 404 (`EVIDENCE_NOT_FOUND` or `EVIDENCE_FILE_NOT_FOUND`) if record or physical file is missing.

4. **Router Registration & Testing:**
   - Mount router under both `/` and `/api/v1` prefixes in `src/eldercare/api/app.py`.
   - Author thorough test suite in `tests/unit/test_api_incidents.py` covering pagination, filtering, 404 handling, streaming binary output, and security boundaries.

## 2. Invariants & Security Constraints

- **Sandboxed Evidence Access:** File access must strictly be mediated by `EvidenceStorage.resolve_safe_path()`; raw or relative path traversal (`../`, `/etc/passwd`, `C:\`) is strictly prohibited.
- **Detector Immutability:** Responses expose detector parameters directly from the immutable database record.
- **Consistent Error Structure:** Error responses must match `{"error": {"code": "...", "message": "...", "request_id": "..."}}`.
- **Fast, Deterministic In-Memory Testing:** Test suite runs against in-memory SQLite and temporary sandbox directory.

## 3. Acceptance Criteria

- `GET /incidents` supports all query parameters and returns accurate counts and records.
- `GET /incidents/{incident_id}` returns full nested relationships and 404 when nonexistent.
- `GET /incidents/{incident_id}/evidence/{evidence_id}` streams verified file contents with proper MIME type and SHA256 header.
- 100% test suite pass rate with 0 regressions.
- Ruff lint and format clean across all files.
