## Scope (only spec-supported items)
- `deployment/mosquitto/mosquitto.conf`: explicit `listener 1883` (+ `protocol mqtt`),
  persistence to `/mosquitto/data/` (matches compose volume), bounded
  `max_connections`/`max_queued_messages`, `log_dest stdout` with non-debug types,
  no websocket/management listeners.
- Auth: no MQTT credentials exist anywhere in specs/settings/compose, so no
  `password_file` is introduced (would be invented scope + break the demo path).
  Anonymous local access is documented EXPLICITLY as a development-only deviation
  with production requirements listed (password_file + ACL + no host port publish).
- Compose: mount conf read-only + `mosquitto` healthcheck via bundled
  `mosquitto_sub` against `$SYS`; vision/ api/agent `depends_on` unchanged in
  semantics (no hard broker dependency introduced — `service_started` only).
- Tests: `tests/unit/test_mqtt_broker_config.py` — conf parses, required
  directives present with exact values, forbidden directives absent
  (websockets, debug log, anonymous remote exposure notes), compose references
  the mounted conf; plus `docker compose config` rehearsal where daemon allows.
