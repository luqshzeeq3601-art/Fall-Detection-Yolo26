## 1. Objectives & Scope

1. **SQLAlchemy 2.0 Models (`src/eldercare/db/models.py`):**
   - `Camera`: id, name, enabled, status, last_frame_at, last_heartbeat_at, reconnect_count, created_at, updated_at.
   - `Incident`: id, camera_id, track_id, started_at, confirmed_at, ended_at, detector_state, fall_score, model_name, model_version, config_version, evidence_features (JSON), created_at. Indexes on `(camera_id, confirmed_at desc)` and `(confirmed_at desc)`.
   - `IncidentEvidence`: id, incident_id, evidence_type, storage_path, mime_type, sha256, captured_at, created_at.
   - `IncidentReview`: id, incident_id, label, notes, reviewer, created_at (append-only review trail).
   - `AgentEnrichment`: id, incident_id, status, provider, model, prompt_version, output (JSON), error_code, duration_ms, created_at, completed_at.
2. **Database Session & Engine Factory (`src/eldercare/db/session.py`):**
   - Provide engine creation, sessionmaker, and dependency injection helpers (`get_db`, `create_session_factory`).
   - Support both PostgreSQL (production) and SQLite (fast, isolated in-memory testing for unit CI) seamlessly.
3. **Alembic Migration Environment (`src/eldercare/db/migrations/` & `alembic.ini`):**
   - Configure Alembic `env.py` pointing to `Base.metadata`.
   - Create initial migration revision `0001_initial_schema.py` creating all 5 tables, indexes, and foreign keys.
4. **Automated Testing:**
   - Model schema & relationship tests (`tests/unit/test_db_models.py`).
   - Alembic migration upgrade / downgrade tests (`tests/integration/test_alembic_migrations.py`).

## 2. Invariants & Constraints

- **No Framework Leakage into Fall Engine:** Database models consume domain outputs (`FallDecision`, `TrackObservation`) without coupling DB models to detection logic.
- **Explicit Primary / Foreign Keys:** Relationships use explicit cascade options.
- **Timezone Awareness:** All timestamps use UTC timezone semantics.
- **No Raw Video in Database:** Evidence table stores only references, hashes, and metadata.
- **CPU & Environment Safety:** Unit tests use in-memory / temporary SQLite databases; normal CI requires no live PostgreSQL server.

## 3. Acceptance Criteria

- All 5 models defined with exact fields per `DATABASE_SCHEMA.md`.
- `alembic upgrade head` and `alembic downgrade base` execute cleanly and reversibly in automated tests.
- 100% test pass rate with 0 regressions across prior phases.
- Ruff lint and formatting pass with 0 errors.
