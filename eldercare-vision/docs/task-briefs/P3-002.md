# P3-002 — Define `TrackObservation` interface

## Purpose
Define a stable, framework-independent `TrackObservation` domain contract — one tracked person observation at one frame/time point — that downstream temporal fall analysis can consume without depending on Ultralytics, ByteTrack, Torch, OpenCV, or tracker-internal objects. Plus a clean conversion boundary from the existing P3-001 tracked output. History buffers (P3-003), expiry (P3-004), and all temporal/fall logic stay out.

## Requirements
- New module `src/eldercare/vision/tracking/observation.py` (stdlib + numpy ONLY at import time; NO ultralytics/torch/cv2 import — not even lazily; reuse Phase 2 value types by import):
  - Frozen `TrackObservation` dataclass. Exact fields, derived from ARCHITECTURE §5 track observation (mapping in parentheses):
    - `camera_id: str` (`camera_id`; non-empty string, pattern lives upstream — mirror `pipeline._check_camera_id` semantics)
    - `track_id: int | None` (`track_id`; `None` = tracker established no ID — explicit, never defaulted-invisibly; otherwise non-negative int, bools rejected — mirror `tracker._check_track_id` semantics)
    - `timestamp: float` (`timestamp`; carries the source capture timestamp; finite `>= 0` — mirror pipeline timestamp semantics; document the meaning)
    - `bbox_xyxy: tuple[float, float, float, float]` (`bbox`; pixel coords, finite, `x1 <= x2`/`y1 <= y2` — mirror `PersonPose` rules)
    - `detection_confidence: float` (verbatim, finite in `[0, 1]` — Phase 2 no-threshold semantics preserved)
    - `keypoints: tuple[Keypoint, ...]` exactly 17 (`keypoints[17]`; REUSE the Phase 2 `Keypoint` type verbatim — no new keypoint type, so missingness (`None` coords + `present=False`) and confidence-preservation semantics carry over unchanged; length ≠ 17 → fail-closed)
    - `keypoint_confidences` are NOT a separate field: they ride inside `keypoints[i].confidence` (single source of truth; a parallel array would invite drift — document this)
    - `image_width: int`, `image_height: int` (positive ints; pixel-coordinate meaning preserved)
  - DELIBERATE OMISSION (reviewer must judge): ARCHITECTURE §5 also names `pose_confidence_summary`. P3-002 does NOT include it: no aggregation policy (mean/min/weighted) exists in any spec, and inventing one here would bake an unjustified semantic into the domain contract. All 17 raw confidences are preserved, so any summary remains computable downstream (temporal engine owns the policy). Record this reasoning in the module docstring.
  - NO `frame_id`: ARCHITECTURE §5 track observation carries no frame identity (history is keyed by `(camera_id, track_id)` per AI_SPEC §5); do not invent fields. Document the omission alongside the summary one.
  - Fail-closed validation on EVERY field (naming `ValueError`/`TypeError`; bools rejected for numerics; NaN/±Inf rejected for scalars; keypoint entries must be `Keypoint` instances; no range policy beyond the Phase 2 rules — no thresholding anywhere).
  - Conversion boundary: `tracked_frame_to_observations(tracked: TrackedFrame, *, camera_id: str, timestamp: float) -> tuple[TrackObservation, ...]` — pure function; validates inputs; preserves person ORDER (index order, unless the architecture requires otherwise — it does not); one observation per input person (zero-person → `()`); per-person `bbox`/`detection_confidence`/`keypoints`/`track_id`/dims copied verbatim (keypoint tuples and persons are immutable value objects — shared references are safe, no deep copy needed; document this); deterministic (repeated calls on equal inputs → equal outputs). `track_id=None` passes through explicitly.
  - Contract-first docstring: field→spec mapping table, the two deliberate omissions with reasons, `None`-means-unassigned, immutability/shared-reference safety, no-retention (no framework objects, no images), what is NOT here (history/expiry/temporal features/velocity/angles/smoothing/fall logic).
- Modify `src/eldercare/vision/tracking/__init__.py` (ADDITIVE ONLY: re-export the new names; docstring stays accurate).
- Tests (TDD, RED first; CPU-only, deterministic; NEVER import `ultralytics`/`torch`/`cv2` in tests; zero sleeps; `sys.modules` + AST framework-freedom proofs following the P2-006/P3-001 pattern):
  - `tests/unit/test_track_observation.py` (new; unique basename): schema construction (valid → all fields preserved bit-exact); one/multi/zero persons via the conversion boundary; `track_id=None` explicit; exact ID preservation (incl. large IDs); bbox bit-exact; 17-keypoint ORDER preserved (index-aligned names spot-check, not a re-assertion of the adapter's tuple); keypoint-confidence bit-exact incl. `0.0`/tiny; missing keypoints (`None` coords, `present=False`, conf preserved) pass through; timestamp/camera/dims propagation; determinism (repeat conversion → `==`); malformed fail-closed PER FIELD (bad camera_id/track_id/timestamp/bbox/conf/keypoints-count/keypoints-type/dims, non-`TrackedFrame` input, missing kwargs); frozen-immutability (`FrozenInstanceError` on set); framework-freedom.
  - Small integration `tests/integration/test_track_observation_sequence.py` (new): 2–3 frame `TrackedFrame` sequence (scripted backend via `PoseTracker`) → per-frame `to_observations` → per-track identity continuity observable WITHOUT tracker knowledge (consumer reads only `TrackObservation` fields).
  - Cap ≤ 30 new tests total. Do NOT duplicate adapter/tracker internals already pinned (Keypoint invariant, IoU math, backend protocol) — test the NEW contract + boundary only; say in the report what was deliberately not re-asserted.
- Downstream-consumability proof (in tests, not new src): a consumer-shaped assertion block that builds bounded per-`(camera_id, track_id)` groupings using ONLY `TrackObservation` fields (proves temporal code needs no tracker knowledge; grouping helper itself is test-local — history buffers remain P3-003).
