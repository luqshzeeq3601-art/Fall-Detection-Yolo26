# Phase 11.8 — Recovery to Deployment Targets (V5)

## Context

Phase 11.7 closed with "PASS / APPROVED" but the held-out result was Recall 41.7%, Precision 33.3%. That is worse than V3-fixed and far below every accuracy target. The review found three kinds of problems:

**Input bug (likely root cause).** Every URFD `.mp4` frame is a side-by-side composite: the left half is a grayscale depth map, the right half is RGB (verified: left-half chroma = 0.00). YOLO poses the person twice, which produces ~146% "track continuity" and noisy ghost tracks. Every V3/V4 number was trained and evaluated on this input.

**Evaluation bugs.**
- `model.track(persist=True)` keeps tracker state across videos.
- Untracked detections are merged into a fake `tid = 1`.
- Any alert anywhere in a fall clip counts as a TP, and TTA is clamped with `max(0, …)`.
- The failure taxonomy is hardcoded and 5 of its 17 entries are wrong.
- Dev recall of 99.73% was scored on training data.
- 103 FPS was a projection from synthetic skeletons. Measured throughput is 48 FPS.
- The gate test never checks accuracy, even though `check_deployment_gates_v4` exists and goes unused.

**Data too small and narrow.** 70 URFD clips with 12 test falls. `datasets/raw/upfall/*.mp4` are synthetic renders from `generate_upfall_*_archives.py`; only 10 real UP-Fall zips exist. There was no long-form negative video, so false alerts per hour were never measured.

**User decisions:**
- Targets are strict 95/95.
- Public datasets only; no own recordings.
- Non-commercial use, so NC licences are allowed.
- The model architecture may be replaced if dev ablation supports it.

## Gate definition (all must pass on Test-A; point estimates, with 95% CIs reported)

| Metric | Target |
|---|---|
| Event-level recall | ≥ 0.95 |
| Event-level precision | ≥ 0.95 |
| Event-level F1 | ≥ 0.95 |
| Long-form false alerts / camera-hour | < 1.0, over ≥ 20 h of non-fall video |
| p95 time-to-alert | ≤ 2.5 s |
| Measured E2E FPS (TensorRT, real decoded video) | ≥ 15 |

**Event matching.** A fall is a TP only if the first alert lands in [fall_start − 1 s, lying_start + 3 s]. Any other alert is an FP.

**Dev exit criteria before Test-A is touched** (the margin guards against optimism): out-of-fold recall ≥ 0.96, precision ≥ 0.96, dev long-form FA/hr ≤ 0.5.

## Stage 3 — Pose cache and front-end quality (P11.8-014…016)
- **P11.8-014.** `scripts/dataset/extract_pose_cache.py` runs YOLO26s-pose TRT + ByteTrack once per clip into the existing keypoint cache (`src/eldercare/fall_engine/cache/`). An `.npz` backend is added to `storage.py` for scale. All model work then runs off the cache without re-running YOLO.
- **P11.8-015.** Resample every track to a common 15 Hz timeline, because source fps ranges from 18 to 30. Missing keypoints stay masked and are never interpolated, per the AGENTS.md rule.
- **P11.8-016.** Measure pose availability on labelled falling and lying frames, per source. Tune `imgsz`, `conf`, and tracker thresholds on dev only.

## Stage 4 — Model ablation ladder V5 (P11.8-017…022)

All candidates use:
- 5-fold CV grouped by (source, subject);
- fixed seeds;
- the same event post-processor: a falling→fallen transition within ≤ 2 s, fallen state sustained ≥ τ s, then cooldown. τ and thresholds are chosen on out-of-fold dev predictions to maximize recall subject to dev FA/hr ≤ 0.5.

| ID | Model |
|---|---|
| M0 | Current V4 stack retrained on the new data (baseline: `features_v3`, `multiscale`, `training_v4.py`) |
| M1 | sklearn HistGradientBoosting on multi-scale hand features |
| M2 | Skeleton temporal CNN/GRU in PyTorch. Input: normalized keypoints (hip-centred, torso-scaled), confidence and mask channels, bbox aspect ratio and velocity. 3 classes: normal / falling / fallen. Window 2–3 s at 15 Hz. |
| M3 | Only if M2 misses target: ST-GCN-lite, or M2 fused with hand features |

- **Augmentation** is train-fold only: flip, scale, rotation, keypoint dropout, and 0.8–1.25× speed jitter. `V4FeatureAugmenter` is the template.
- **Hard-negative mining.** Run on dev long-form video, add false-alert windows to training, and repeat for up to 3 rounds.
- **Ablation.** Add the ADL suppressor, camera normalizer, and multiscale windows on top of the best model. Each is kept only if it shows an out-of-fold gain.
- **Export.** New `pipeline_v5.py` exports to ONNX Runtime or NumPy. Budget: ≤ 5 ms/track at p95.
- **Fallback levers if dev plateaus below 0.96**, in order. Levers 2 and 3 need ADR-010 plus benchmark evidence, per AGENTS.md.
  1. More hard negatives, plus Le2i and MCFD views.
  2. yolo26m-pose TRT.
  3. Fine-tune pose on fall/lying frames with pseudo-labels from a larger teacher model.
  4. Stop and report honestly; re-scoping the targets is the user's call.

## Honest limits
- The data is public and staged. Passing the gate proves in-domain accuracy on public staged falls plus the false-alert rate on real seniors' daily life (Toyota Smarthome). It does **not** prove performance in a specific room or camera.
- A shadow-mode pilot (alerts go to a human, nothing is auto-acted on) is still required before relying on the system.
- 95/95 on public data may not be reachable. The fallback ladder and stop rule make that visible instead of hiding it.
